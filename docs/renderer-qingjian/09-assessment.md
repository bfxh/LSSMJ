# 09 · 对标评估：现状边界、可吸收清单、测量建议

> 本评估分两层：
> ① **现状实现的能力/边界/成本**——证据来自本仓对 `qingjian-render` 的逐行精读（账本 `w5a.jsonl`，125 条）；
> ② **对标吸收清单**——由本仓大分析工程的引擎/论文轨道（`../engines/**`、`../papers/**`、`../platforms/**`）支撑。
> 本节所有"吸收/不吸收"判定都要求能指到证据条目；**引入外部结论时标注估计量口径差异**（别跨口径套结论）。

## 9.1 现状定位：它适合什么、不适合什么（据 W5A 条目）

**适合**（当前实现的原生目标，全部有锚，见 `01`–`08`）：

- 小面积、按键驱动的**显示面**：候选窗（竖排/横排/矩阵）、悬浮状态条。全画一帧在
  266×300pt @2x 量级（`docs/design/rendering.md:87`）。
- **每帧全画**可接受：无脏区/局部重绘机制（`canvas.rs:64` 的 `fill_path` 无剪辑、无分层缓存），
  文本量小使代价可控。
- 单线程 UI 线程内同步出帧：Windows 一份共享渲染器（`painter/mod.rs:16`）。

**不适合（当前实现的能力边界，全部是"未实现"而非"做不了"）**：

| 场景 | 限制 | 证据 |
| --- | --- | --- |
| 大面积滚动列表/长文档 | 无脏区、无图集、无分块 | `05` §5.1（原语只有矩形/路径/位图混合） |
| 富视觉（渐变/毛玻璃/图片装饰） | `Paint` 永远单色 | `canvas.rs:148`；设计档方向 `rendering.md:112` |
| 多窗口/图层合成 | 无 layer/合成概念（状态条+候选窗各出一张位图） | `renderer/status/rendered.rs:9` 的契约面 |
| GPU 加速/大分辨率面 | 明确不上 GPU（该尺寸下 GPU 是负担） | `rendering.md:60` |
| 文本输入框/编辑器类控件 | 单行文本、无光标排版语义（自带光标只服务拼音行） | `text/mod.rs:1`（单行假设） |

## 9.2 已对齐原生的证据链（"像不像"有判据）

1. **宽度**：`trak` 字距 + `opsz=17` 补丁 + 覆盖率 gamma 三件套后，"hello / ni'hao / 1/6 /
   phr. you change" 三字号宽度与 `NSAttributedString.size()` 到小数点后两位相等（`rendering.md:95`）。
2. **字形归属**：`zh-CN` 下汉字落 PingFang SC、假名落 Hiragino Sans（W3→W4 教训，`rendering.md:105`）；
   探针工具 `trace_families`（`text/mod.rs:137`）。
3. **观感**：深浅色、纠错删除线、云端词、状态条、齿轮、热切换均在 macOS spike 与 Win11 真机过
   （`rendering.md:82`–`:87`、`:123`）；残留差异 ≤1pt/字，已逐条留档（`rendering.md:98`–`:102`）。

## 9.3 已识别的优化点（不虚报收益，只记方向与锚）

| 项 | 锚 | 方向 |

| measure/draw 双整形（竖/横排） | `renderer/vertical.rs:63`、`renderer/horizontal.rs:84` | 把 measure 结果传进 draw（矩阵的估算快路径已是同族先例，`matrix.rs:202`） |

## 9.5 测量建议（下一步做成判据；目前**均未执行**）

**建议协议**（对齐本仓既有的测量纪律：交错 A/B、窗口均值、仪器与被测解耦）：

1. **分相计时**：字体库加载 / measure / draw（含字形栅格）/ 阴影 / 贴图，五相各记 us；
   仪器放在 `renderer/mod.rs` 的 render 内与壳的贴图调用处（`painter/mod.rs:93` 已有 debug 日志可挂）。
2. **稳态分布**：同一帧连续渲染 N≥300 次，报 P50/P95/P99 与 max；**单点不算数，窗口均值**。
3. **尺寸扫描**：{266×300, 400×500, 矩阵 9 列满页} × {scale 1,2} 的参数矩阵，找超线性拐点。
4. **内存稳态**：进程 RSS 随帧数曲线（区分字体库/字形缓存/单帧缓冲三块）。
5. **金丝雀**：渲染同一帧两次逐像素比对（应逐位相同）——校验"帧间状态泄漏"。
6. **回退口径**：与 `renderer="system"`（GDI/AppKit）在同机交错 A/B，报比值不报绝对值（跨机不可比）。

**预期用途**：①验证 `rendering.md:73` 的换入门槛（首帧/内存不劣化）在**稳态**下依然成立；
②为 9.3 的每项优化提供前后判据；③将 8.2 的单点读数升级为分布口径。
