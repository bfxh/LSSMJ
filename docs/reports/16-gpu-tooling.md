## TL;DR（每条带锚）

1. **抓帧器不是计时器（第一条铁律）**：RenderDoc 官方 FAQ 自述"开启抓帧会让计时改变、内存（有时多很多）被分配"（W7B-001）；回放不是完美复现、只用于归因（W7B-002），AMD 官方独立互证回放态与正常跑存在"预期差异"（W7B-069）。**C1 的 GPU 帧时读数不得在抓帧器挂载态采集。**
2. **低干扰档是另一条腿**：Nsight GPU Trace="minimal overhead for non-biased activity data"（W7B-011）；PIX 计时捕获"realtime + minimal overhead"（W7B-023），附加数据逐项加成本（W7B-024）——**测量档位=精度×成本，要显式登记**。
3. **系统级证据面存在且非侵入**：GPUView 走 ETL（内核事件）不注入（W7B-033/034），记录全部 CPU 上下文切换（含栈与原因，W7B-035）；GPU 硬件队列=实际工作、Flip Queue=显示对账（W7B-036/037）。
4. **HAGS 是读数条件，不是细节**：官方定义调度卸载（W7B-039）与"延迟↔提交/调度开销"根本张力（W7B-040）；PresentMon 官方 caveat 量化代价——HAGS 开启时 `msGPUActive` 可能偏大约 0.5ms（W7B-043/044）。**读数四件套加"HAGS 状态"。**
5. **D3D12 时间戳六个口径**：按队列频率（W7B-060/065）、管底（BOP）采样=前序工作完成时刻（W7B-061）、空闲时钟停走→关联漂移（W7B-062）、浮点换算（W7B-063）、只用 EndQuery（W7B-064）、拷贝队列为可选能力（W7B-068）。
6. **Vulkan 时间戳两点+一前提**：有效位随队列族 `timestampValidBits`（W7B-055）、`timestampPeriod`=每 tick 纳秒（W7B-056）；CPU↔GPU 同轴靠标定扩展（W7B-057）——**没有标定，提交→执行延迟不可算**。
7. **计数器面各自为政**：RenderDoc 计数器按事件逐条采（W7B-005）但硬件计数器依赖厂商库/平台（W7B-006）；Vulkan 性能查询带"并发受影响"精度标志（W7B-058/059）；RGP 把剖析自身开销（SQTT 写显存）显式记账（W7B-019）。
8. **呈现链决定延迟下限**：flip model 为官方推荐默认（W7B-049）；Independent Flip 可到 1 帧延迟、须标注组合态（W7B-050）；DXGI waitable 与 Vulkan present_wait 是两条对应事件源（W7B-047/048/052/053）；IMMEDIATE/MAILBOX 是"未被 vsync 限速"的吞吐档（W7B-051）。
9. **工具链会死，判据不能押注单一工具**：Intel GPA 官宣 EOL（2025.1 终版、2026 停发，W7B-029）；PIX 官方文档自述"此页为旧版功能"（W7B-027）——引用前核版本，判据里不写死停更件。
10. **对 LSSMJ 的落地**：P3 起按"四档测量模式"立图形侧协议（§3）；C1/C7–C10 的测量含义逐条在账本 lesson。**任一 GPU 档读数没走四档口径，不算读数。**

## 1. 工具全景（五族）

### 1.1 抓帧器（单帧全量回放）

- **RenderDoc**（无厂商绑定）：激活捕获后逐条 API 调用全序列化（W7B-003）；捕获成本=计时改变+内存峰值（W7B-001/008）；回放器自身最慢操作是部分帧回放（W7B-004）；计数器查看器逐事件采 GPU 计数器（W7B-005），硬件计数器经 AMD GPA 库且限定平台（W7B-006）；应用内 API 可程序化抓帧（W7B-009）与多帧连拍（W7B-010）。
- **NVIDIA Nsight Graphics**：最小开销、非偏置活动数据（W7B-011）；跨帧自动追踪着色器执行（SM 深剖析，W7B-012）；Perf SDK 从应用直接收集指标+HUD（W7B-013）。系统侧 Nsight Systems 给 CPU-GPU 统一时间线（W7B-014）。
- **AMD RGP**：底层优化定位（W7B-016），profile 两类数据=命令缓冲计时+SQTT（W7B-017）；帧内事件=命令缓冲内的一次 API 调用（W7B-070）；profile 由 Radeon Developer Panel 生成；占用视图的限制因子着色（W7B-071）与 CPU/GPU 界分启发式（W7B-018）；剖析开销（SQTT 写显存）显式记账（W7B-019）；与 RenderDoc 联动限定 DX12/VK（W7B-020）。RGA=离线编译+静态分析（W7B-021）；RGD=GPU 崩溃后验（W7B-022）。
- **Microsoft PIX**：抓帧与计时两类捕获入口（CLI：pixtool.exe，W7B-028）；GPU 序事件表按 GPU 起始时间建层级（W7B-025）；fence 唤醒关联箭头自动追踪（W7B-026）。
- **Intel GPA**：System/Trace/Frame Analyzer 三件套（W7B-030/031）与连续多帧流（W7B-032）——**已 EOL**（W7B-029），只借模式不押依赖。

### 1.2 系统级（不注入，看全局）

- **GPUView**（WPT/ADK 组件）：ETL 输入、图形化时间线（W7B-033/034）；事件面=全 CPU 上下文切换（含栈与原因）+内核进出+GPU 事件（W7B-035）；GPU Hardware Queue=硬件实际工作（W7B-036）；Flip Queue=显示对账（W7B-037）。
- **WPT 带（WPR/WPA）**：深度性能剖析（W7B-038）；与 GPUView 同源分发。
- **PresentMon**：每帧 CPU/GPU/Display 时长与延迟，跨 API（D3D/GL/VK）+UWP（W7B-042）；MsGPUTime 定义（W7B-045）；MsAllInputToPhotonLatency 定义（W7B-046）；HAGS 与 GL/VK 的精度 caveat（W7B-043/044/072）。

### 1.3 API 内测量（应用自己打点）

- **D3D12**：频率按队列（W7B-060，API 语义 W7B-065）、时间戳=管底操作（W7B-061）、空闲时钟停走→漂移（W7B-062）、浮点换算（W7B-063）、EndQuery-only（W7B-064）、拷贝队列可选（W7B-068）；官方建议先 PIX 后自研（W7B-066）。
- **Vulkan**：时间戳=设备生成整数（W7B-054）、有效位随队列族（W7B-055）、timestampPeriod（W7B-056）；标定扩展对双时域（W7B-057）；性能查询计数器（W7B-058）+并发影响标志（W7B-059）。
- **计数器**：RenderDoc 查看器（W7B-005）、RGP counter views（W7B-019 同页）、厂商库依赖（W7B-006）。

### 1.4 呈现与帧节奏

- **DXGI**：waitable object 语义与使用规约（W7B-047/048）；flip model 官方推荐（W7B-049）；Independent Flip 1 帧延迟+组合态标注（W7B-050）。
- **Vulkan**：present mode 语义（IMMEDIATE 撕裂档，W7B-051）；present_wait 的 pacing 用途与"可见即完成"语义（W7B-052/053）。

### 1.5 方法论与流程

- 官方"先工具后自研"（W7B-066）；CI=程序化捕获+自动抓帧（W7B-067/028）；多帧流+尖峰定位（W7B-032）；崩溃后验（W7B-022）；帧时与延迟分账（W7B-040）；端到端延迟=应用侧标记法（Reflex，W7B-015）。

## 2. 关键机制（口径摘录）

### 2.1 抓帧的成本结构
抓帧=把帧的**全部 API 调用与初始资源状态**序列化（W7B-003）；代价三件：计时改变+内存峰值（W7B-001/008）、时序相关 bug 可能消失或不可复现（W7B-002/007）；连拍模式（W7B-010）适合分布而不适合"计时"。→ 用法边界：**抓帧只做归因，不做读数**；要读数走实时档（W7B-011/023）或 API 打点（W7B-060）。

### 2.2 时间戳精度口径（读数换算链）
| 口径点 | D3D12 | Vulkan |
| --- | --- | --- |
| 频率/周期 | 逐队列 Hz（W7B-060/065） | `timestampPeriod` 纳秒/tick（W7B-056） |
| 分辨率 | —（UINT64 ticks） | 有效位随队列族（W7B-055） |
| 采样语义 | BOP=前序工作完成（W7B-061） | 单调追踪命令执行（W7B-054） |
| 漂移 | 空闲停走；SetStablePowerState 防漂（W7B-062） | 双时域须标定（W7B-057） |
| 换算 | 浮点除法（W7B-063） | — |
→ **读数格式契约（图形侧）**：`{队列, 频率/周期, 有效位, 采样点语义, 时钟状态}` 五元组随数值记录，缺一项即不可复算。

### 2.3 计数器能力面
能力按平台/厂商分裂（W7B-006）；结果带"并发受影响"条件（W7B-059）；RGP 用占用视图的限制因子着色把瓶颈分类（W7B-071）；厂商计数器不能进长期判据（只能做旁证）——与"web 只能旁证"同级的证据分层。

### 2.4 呈现链与延迟
pacing 的两种事件源语义等价（DXGI waitable W7B-047/048 ↔ Vulkan present_wait W7B-052/053）；延迟下限受组合态控制（W7B-050）；HAGS 改变调度路径且动到测量精度（W7B-039/043/044）；帧时与延迟是两条曲线（W7B-040）。

## 3. 给 LSSMJ 的图形侧测量协议（草案，P3 前置；接 `09` 的 P1–P10）

### 3.1 四档测量模式矩阵（任何 GPU 档读数必须声明档位）

| 档 | 工具/手段 | 开销 | 用途 | 不适用 |
| --- | --- | --- | --- | --- |
| A 抓帧归因 | RenderDoc / Nsight Graphics / PIX GPU capture / RGP | 高（计时变、内存涨）W7B-001/008 | 归因：谁贵、哪一帧、哪个 draw | **不得用于帧时读数**（W7B-001） |

### 3.2 与 P1–P10 的对接
- **P1 先打点**：官方同款口径=先 PIX 后自研（W7B-066）；GPU 档首读数走 B/C 档，再决定是否上 D 档。
- **P3 分布**：B 档（PresentMon 每帧指标，W7B-042/045）直接给分布面；C 档给上下文（W7B-035）。
- **P5 交错 A/B**：C10 三级降级（wgpu 三后端→GL→CPU）用同档位同场景交错；切换读数注明 API 维度（W7B-020 的工具能力按 API 分档同理）。
- **P6 仪器不改被测**：抓帧档会改（W7B-001）→ 仪器档位=实验条件的一部分，随读数登记。
- **P8 金丝雀**：渲染 bug 不保证跨环境重现（W7B-007）→ 金丝雀必须写进门，"不重现"不算通过。
- **P9 棘轮**：CI 化=程序化捕获（W7B-067/028/009）；离线静态档（W7B-021）可在无 GPU 环境先跑。
- **P10 按帧预算**：帧时分子用 MsGPUTime（W7B-045）或 D 档时间戳（W7B-060..064），分母场景矩阵不变。

## 4. 坑与反例（负面留档）

1. **"抓帧看性能"是最常见的误用**：计时会变（W7B-001）、回放≠复现（W7B-002/069）——两个独立来源（RenderDoc FAQ × AMD RGP 联动文档）都写死了这条。
2. **HAGS 状态污染 GPU 指标**：官方明说精度下降、量级 ~0.5ms 与预算同阶（W7B-043/044）；同时 GPU 时钟空闲停走会让关联漂移（W7B-062）。
3. **文档与工具的生命周期**：PIX 文档页自述"旧版功能"（W7B-027）；Intel GPA 停更（W7B-029）——"锚是时间戳"在工具面同样成立。
4. **能力假设都会翻车**：拷贝队列时间戳是可选（W7B-068）；DX12/VK 联动白名单（W7B-020）；GL/VK 插桩更少（W7B-072）。
5. **协议性坑**：时间戳只用 EndQuery（W7B-064）；换算必须浮点（W7B-063）；waitable 句柄首帧也要等（W7B-048）。
