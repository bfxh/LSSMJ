## TL;DR（10 条，每条带锚）

1. **显存管理的官方策略就三步：分类、预算、流送**（D3D12 "classify, budget and stream"，`W12A-025`）。
   预算是运行时量：驻留预算随后台进程与用户切换**波动甚至剧烈变化**（`W12A-029`），
   且 `QueryVideoMemoryInfo` 明确要求应用自己把用量保持在进程预算内（`W12A-031`）。
   Vulkan 侧对应 `heapBudget`/`heapUsage` 成对可读（`W12A-036/037`）⇒ **自记账与驱动用量必须双向对账**。
2. **"已分配"与"已驻留"是两个状态**：GPU 尚无缺页能力，数据必须在可能被访问前提交进物理内存
   （making resident，`W12A-027`）；逐出可分页到磁盘，但**销毁比逐出更可靠**（`W12A-028`）；
   优先级算法决定逐出顺序（`W12A-030`），Vulkan 有对应的内存优先级参数（`W12A-038`）。
   LSSMJ 必须显式建模驻留状态，使用未驻留资源=错误，而不是隐式同步。
3. **分配模型是"堆 → 类型 → 子分配"三级**：Vulkan 用 memory heap 与 memory type 两级描述（`W12A-033`），
   资源的 size/alignment/可接受类型由 `VkMemoryRequirements` 查询（`W12A-034`）；
   规范明确应用应当**在一个 allocation 内正确子分配对象**（`W12A-035`），D3D12 也把
   "Suballocation Within Heaps" 单列（`W12A-026`）；只有硬件/驱动要求时才走**专用分配**（`W12A-040`）。
4. **分配器有现成的 Rust 参考实现**：Bevy 的 slab allocator 把大量小对象合并进少量 slab 缓冲（`W12A-009`），
   内部用 OffsetAllocator 式偏移分配、从小的尺寸按需增长到上限（`W12A-010`），
   并把参数定义为"碎片 vs 其他目标"的权衡（`W12A-011`）；分配走 **allocate → commit 两阶段**（`W12A-012`）。
   LSSMJ 可以直接照这套结构写第一个分配器，再按需替换。
5. **记账要用驱动给出的真实尺寸**：Godot 逐资源累加 `buffer_memory`（`W12A-003`），
   纹理用 `texture_get_allocation_size`（驱动实际分配，含对齐/mip）而不是宽高估算（`W12A-004`）；
   Skia 的全局统计把 **budgeted/unbudgeted 与 purgeable/nonpurgeable 分别累计**（`W12A-023/024`）。
   ⇒ 显存 HUD 要同时显示"总量/受预算量/可回收量"，压力策略按**可回收量**决策。
6. **生命周期靠"依赖图 + 句柄引用"，不靠 GC 兜底**：Godot 释放前递归擦除依赖
   （`_free_dependencies`，`W12A-005`；注释明确"先递归擦依赖再释放本体"，`W12A-006`）；
   Bevy 的渲染资源只在**最后一个 handle 被丢弃**时移除（`W12A-015`），并提供显式卸载路径（`W12A-016`）；
   Skia 在引用计数归零前给回调挂点（`W12A-022`）。LSSMJ 的销毁顺序要写成不变量并进单测。
7. **淘汰检查要放在申请路径上，且资源分"可回收/钉住"两类**：Skia 在 add 新记录时就做一次
   purge check（`W12A-018`），对非 discardable 的固定预算资源只按单条上限裁剪（`W12A-019`），
   条目自带 `canBePurged()`（`W12A-020`），GPU 资源带 `isPurgeable()`（`W12A-021`）。
   ⇒ "申请时回收 + 钉子总量也受限"是 LSSMJ 的默认语义。
8. **上传与回读是两条独立管线**：上传侧用**统一 staging 池 + 批量 copy**（D3D12 `W12A-032`），
   Godot 的 staging block 用 CPU 内存类型并复用（`W12A-002`）；回读侧一律异步
   （wgpu `map_async` + 回调，`W12A-013`）并通过**有界通道**回传（容量 1，天然背压/丢旧，`W12A-014`）。
   LSSMJ 的上传/回读都必须计入帧预算（带宽也是成本），回读要有延迟上限与丢帧策略。
9. **设备上限是分配器的输入**：WebGPU/wgpu 把 `maxBufferSize`、`maxTextureDimension2D`、
   `maxStorageBufferBindingSize` 等作为设备限制显式暴露（`W12A-041/042/043`）；
   Metal 的堆内子分配共享存储模式、purgeable 只在堆粒度生效（`W12A-044`），
   资源必须选存储模式（含 memoryless，`W12A-045`），堆内分配是显式 offset（`W12A-046`）。
   LSSMJ 的分配器在创建路径就按设备上限分块/降档，超限资源在资产导入期就报红。
10. **碎片与虚拟内存是长期方向，不进默认档**：GPU 内存压缩/去碎片是独立研究课题（`W12A-050`），
    swap-aware 调度把重建成本纳入逐出代价（`W12A-051`），虚拟内存/稀疏驻留在 2025 年仍在推进
    （`W12A-052`）。LSSMJ 预留稀疏/虚拟资源接口，但默认档走"子分配 + 驻留预算 + 优先级逐出"三件套。

## 1. 资源管理模型（四层 + 一次对账）

```text
配额层      设备查询：预算（heapBudget / QueryVideoMemoryInfo）+ 上限（wgpu Limits）    W12A-029/031/036/043
    │  ① 自记账（缓冲/纹理分账，驱动真实尺寸）+ 与驱动用量对账
    ▼
分配层      堆（本地/主机可见）→ 类型 → 子分配（slab/offset）+ 专用分配豁免            W12A-026/033/034/035/040
    │  ② 两类资源：可回收 / 钉住（钉子也计入上限）
    ▼
驻留层      已分配 ≠ 已驻留；优先级 + 逐出/销毁；延迟分配用于临时附件                 W12A-027/028/030/038/039
    │  ③ 销毁优先（可重建资源），逐出/分页第二档
    ▼
生命周期层  依赖图（先依赖后本体）+ 句柄引用决定回收 + 归零前回调 + 帧阶段固定        W12A-005/006/015/016/017/022
    │
    └── 上传/回读：统一 staging 池 + 批量 copy；异步 map + 有界通道                    W12A-002/013/014/032
```

一次对账：每帧（或 N 帧）比较**引擎自记账**与**驱动用量**；偏差超阈值=有未记账分配（红）。
这条对账是预算门的前置——账错了，后面所有策略都是错的。

## 3. 重点来源短分析（5 份）

### 3.1 D3D12 内存管理/驻留——"分类、预算、流送"的官方三步

- 三步策略（`W12A-025`）、堆内子分配（`W12A-026`）、驻留语义（`W12A-027`）、逐出 vs 销毁（`W12A-028`）、
  预算波动（`W12A-029`）、优先级算法（`W12A-030`）、QueryVideoMemoryInfo 的应用责任（`W12A-031`）、
  统一上传缓冲（`W12A-032`）。
- 结论：**LSSMJ 的资源层直接以这三步为骨架**；预算与驻留是引擎责任，不是"驱动会处理"。

### 3.2 Vulkan 内存章节 + VK_EXT_memory_budget——跨平台内存模型

- 堆/类型模型（`W12A-033`）、`VkMemoryRequirements`（`W12A-034`）、子分配（`W12A-035`）、
  内存优先级（`W12A-038`）、延迟分配（`W12A-039`）、专用分配（`W12A-040`）、
  以及 `heapBudget`/`heapUsage`（`W12A-036/037`）。
- 结论：**D3D12 与 Vulkan 的抽象在 LSSMJ 层可统一为「预算 + 驻留 + 优先级 + 子分配」四件事**；
  wgpu 未统一暴露预算时，各后端分别接（有界），但抽象接口先立住。

### 3.3 Bevy slab allocator + readback——Rust 侧的第一个实现参照

- slab 结构（`W12A-009`）、OffsetAllocator 与增长（`W12A-010`）、碎片权衡参数（`W12A-011`）、
  两阶段分配（`W12A-012`）；回读的异步 map（`W12A-013`）与有界通道（`W12A-014`）；
  资源生命周期（最后一个 handle 丢弃才移除，`W12A-015`；显式卸载，`W12A-016`；帧阶段固定，`W12A-017`）。
- 结论：**LSSMJ 的分配器与资源生命周期以 Bevy 为第一参照**（同语言、同 wgpu 栈），
  差异点只在"显存预算/驻留"这层（Bevy 未做，需要自研）。

### 3.4 Godot RenderingDevice——显式 GPU 资源 API 与依赖释放

- 内存分配类型/用途位显式（`W12A-001`）、staging 复用（`W12A-002`）、
  缓冲/纹理记账（`W12A-003/004`）、依赖递归释放（`W12A-005/006`）、
  渲染图用途→屏障（`W12A-007`）与驱动能力位（`W12A-008`）。
- 结论：**LSSMJ 的 GPU 资源层照 Godot 的"显式 API + 依赖图 + 用途声明"**，
  并把驱动能力差异（是否遵循显式屏障）作为可探测位。

### 3.5 Skia 资源缓存/统计——淘汰与"可回收量"

- add 时 purge check（`W12A-018`）、固定预算与可丢弃之分（`W12A-019`）、
  `canBePurged()`（`W12A-020`）、GPU 资源 `isPurgeable()`（`W12A-021`）、
  归零前回调（`W12A-022`）、budgeted/unbudgeted 与 purgeable/nonpurgeable 统计（`W12A-023/024`）。
- 结论：**LSSMJ 的缓存淘汰语义照 Skia**；显存 HUD 的"可回收量"直接来自这套分类。

## 4. 与既有轮的接缝

- **与 w6a（纹理/SVT/流送）**：w6a 定的是"哪些纹理该在显存里"（页表/流送）；本轮定的是
  "显存怎么分配、怎么记账、超预算怎么回收"。接口=资源描述（尺寸/格式/用途）→ 分配器 → 驻留状态。
- **与 w8b（压缩）**：压缩减少单位资源的字节数；本轮决定这些字节放在哪、能放多少。接缝=压缩后的实际分配尺寸
  （`W12A-004`）。
- **与 w2b/w6f（wgpu/图形 API）**：wgpu 提供资源创建/`Limits`/`map_async`；预算与驻留需按后端补（有界）。
  本轮给的是 wgpu 之上的抽象层设计。
- **与 w9c/w11a（帧阶段与输入）**：资源准备/上传/释放落在固定帧阶段（`W12A-017`），
  与输入的"帧末 flush / 帧中敏捷 flush"是同一套阶段纪律。
- **与 w10b（色彩/显示链）**：HDR/宽色域会显著抬高纹理与中间 RT 的显存占用；显示链的能力档
  必须与显存预算联合决策（同一条降级链）。

## 5. 未验证项（缺什么证据）

1. **未运行任何上游代码**：全部为文档/源码静态观察；分配器正确性、碎片率、逐出收益、回读延迟
   都要在引擎代码期实测。
2. **无实测显存数据**：没有 LSSMJ 目标场景的显存占用曲线、预算波动幅度、逐出/重建时间；
   本报告只给模型与判定表。
3. **wgpu 的预算/驻留能力未逐版本核**：本轮读了 wgpu `Limits` 与 Bevy 的 readback 用法，
   但 wgpu 是否/如何暴露显存预算、memory hints、资源驻留语义未逐条核（落地需锁版本 + 特性探测）。
4. **Metal 只到 JSON 摘要层**：MTLHeap/MTLResource 的完整 API（heap 容量查询、purgeable 状态机、
   memoryless 细节）未逐节核；`W12A-044/045/046` 只支撑"堆/存储模式/子分配"三个结构性结论。
5. **Android 图形内存文档未取**：`developer.android.com`/`source.android.com` 在本机网络超时
   （与 w10b/w11a 同因）；Android 的显存/共享内存策略未进账本。
6. **D3D12 "copying and accessing resource data" 页 404**：上传侧只取到
   "Uploading different types of resources"（`W12A-032`）；读回/copy 队列的细节未逐字核。
7. **虚拟内存/稀疏资源只到论文层**：`W12A-052` 是 DNN 训练场景，与实时渲染的映射路径差异较大；
   实时渲染的稀疏驻留收益未验证。
8. **碎片治理只到研究层**：compaction（`W12A-050`）与 swap-aware（`W12A-051`）都没有在实时渲染器上的
   公开读数；本轮只把碎片率列为观测指标，治理策略留压力档。

> **补锚更新（w14a）**：第 3 项（wgpu 内存提示）、第 4 项（Metal 存储模式）已补——`MemoryHints::{Performance,MemoryUsage,Manual}` + `DeviceDescriptor.memory_hints`（`W14A-026/027`）；`MTLStorageMode` 四档 shared/private/managed/memoryless（`W14A-028/029`）。第 5 项（Android）部分补（色彩/HDR 已取，图形内存页仍未取）；第 6 项（D3D12 copy 页）部分补（改用资源屏障页：`COPY_DEST` 初始状态硬约束与状态提升，`W14A-024/025`）。
