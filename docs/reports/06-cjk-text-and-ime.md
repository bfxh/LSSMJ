## TL;DR（每条带锚：`W3E-0xx` → 账本行；URL 见账本 anchor）

1. **挤压必须排在禁则之前**（clreq：`标点挤压处理会影响换行位置`）；禁则严格度是“排版风格”档位，实现可自选宽/严（`W3E-001/002`，clreq §换行与断词连字）。
2. **行末全角标点压半角的国标依据**：GB/T 15834—2011 第 5.1.10 条“若为全角字符则应占半角字符的宽度（即半个字位置）”；行内逗/顿/分号最小压到半字、中西间距最小 1/8 em（`W3E-004/005/006`，clreq §标点宽度调整/行内调整）。
3. **短行要放宽禁则，这是规范自己的结论**：jlreq 指出行短时调整点少、字间调整会“极端”，报纸（短行）因此允许 ？/！起行——候选窗正是短行（`W3E-016`，jlreq §行頭禁則）。
4. **竖排不是旋转**：UAX#50 用四类属性（U 直立 / R 旋转 / Tu,Tr 需换字形+各自回退方向）表达，替换字形“最终取决于字体表（'vert' 特性）”（`W3E-022/023/024`）。
5. **竖排的工程口径（CSS Writing Modes）**：书写模式=`writing-mode + direction + text-orientation` 三元组；直立排字**必须**启用 `vert`；CSS 明确**不用** `vrt2`；直立状态下破折号/括号类仍要旋转（`W3E-025/026/027/028`）。
6. **CJK 挤压/断行的 Web 实现档位**：`line-break: loose` 规范点名“典型用于短行”；`text-spacing-trim` 六档枚举（`space-all | normal | space-first | trim-start | trim-both | trim-all`）；`trim-both` 语义=行首开标/行尾闭标用半宽字形+标点间折叠（`W3E-029/030/031`）。
7. **断行实现不需要词典**：ICU 自述“日文分词用词典，但断行不用”；Rust 侧现成件 `unicode-linebreak`=UAX#14 实现、表由 `LineBreak.txt` 生成（`W3E-033/035/036`）。
8. **同一码位、不同地域字形**：Noto/Source Han 给两条路（选对应语言字体 / 语言标注触发 `locl`），且**支持语言标注的应用很少**；微软雅黑/正黑自带 `dlng` 默认语言元数据（`W3E-039/040/041/043/044`）。
9. **候选窗 UI 惯例（可抄的具体数字）**：Rime 页大小默认 5（范围 1–9）、`style/horizontal`/`inline_preedit` 独立开关、高亮候选是独立“光棒”色；Fcitx5 尺寸=内容边距+文本边距+文本尺寸，竖排候选可配但“引擎逻辑可覆盖方向”（`W3E-051/052/053/054/055/056`）。
10. **平台契约**：Wayland 把候选窗定义为**短生命周期 popup surface、锚定光标区**（失焦即销毁）；iOS 自绘键盘**宽度由系统强制=屏宽**（只可调高）、`secureTextEntry` 字段强制退回系统键盘；Android 候选视图固定位于软键盘上方（`W3E-058/059/062/063`，`W3E-060/061` source）。

## 2. 关键机制（对“单行 + 截断 + 可选竖排档”的取舍）

### 2.1 挤压与禁则（顺序与档位）

- **顺序**：clreq 要求“在处理禁则之前，应优先……处理标点挤压”，理由是挤压**会改变换行位置**（`W3E-001`）。
  实现上的直接含义：挤压不是禁则的补丁，而是断行求解的**输入**（先算宽度，再断行）。
- **档位**：禁则严格度被明确为“排版风格”，用户代理可自选更宽松或更严格（`W3E-002`）；CSS 侧对应
  `line-break: strict | normal | loose`，其中 **loose 的规范说明就是“短行（如报纸）”**（`W3E-029`）。
  ⇒ **取舍**：LSSMJ 候选窗（短行、单行）默认取 **loose**；严格档保留为实现档位但不默认。
- **量值**：行末全角标点占半角（GB/T 15834—2011 5.1.10，`W3E-004`）；行内逗/顿/分号最小压到半字宽
  （`W3E-005`）；中西间距最小 1/8 em、多处须等量（`W3E-006`）；调整原则是**先挤压后拉伸**（`W3E-007`）。
  ⇒ **取舍**：截断（单行→省略号）只需实现“行末标点=半宽”一条；其余量值进多行档的测试用例集。
- **均排与悬挂**：禁则造成的空档用均排吸收，但**段落末行/单行段落不用均排**（`W3E-008`）——单行文本
  的宽度口径因此更简单；悬挂点号在中文出版物中并非惯例（`W3E-009`），jlreq 侧悬挂也仅限句点/读点两类
  且 JIS X 4051 未正式规定（`W3E-015`）。⇒ **取舍**：默认不做悬挂。

### 2.2 断行与截断

- 断行**不需要词典**：ICU 自述“日文分词用词典，但断行不用”（`W3E-033`）；边界状态要区分“强制换行”
  与“可行断点”（`W3E-034`）⇒ 截断实现里的“可否在此断开”与“必须断开”是两类标记。
- Rust 现成件：`unicode-linebreak` 自述为 UAX#14 实现（`W3E-035`），表由 `LineBreak.txt` 生成、改数据须重生成
  （`W3E-036`）⇒ **取舍**：若未来做截断/换行，依赖该 crate；不自造规则表（与 parley/cosmic-text 同口径）。
- 短行的宽松依据来自 jlreq 的动机陈述（`W3E-016`）与 CSS loose 档（`W3E-029`）**两处独立来源**。

### 2.3 竖排档（可选档）

- **模型**：UAX#50 定义 `Vertical_Orientation` 四值：U（直立）、R（旋转 90°）、Tu/Tr（需换字形，回退方向
  分别为直立/旋转）（`W3E-022/023`）；替换字形最终取决于字体表（如 `vert` 特性是否存在）（`W3E-024`）。
- **工程口径**（CSS Writing Modes 4）：书写模式=`writing-mode + direction + text-orientation`（`W3E-025`）；
  直立排字必须启用 `vert`（`W3E-026`）；CSS **不使用** `vrt2`，朝向由 UAX#50 决定（`W3E-027`）；
  即便“直立”，破折号/括号类仍要旋转（`W3E-028`）。
- **GTK 侧参照**：Pango 用 gravity（按脚本+基准+hint 逐段解析）实现竖排（`W3E-065`）。
- **日文对照**：纵组不只是旋转——装订侧翻转（`W3E-019`）、小写假名字面位置随组方向改变（`W3E-020`）、
  行间元素（ルビ等）不得改变行距（`W3E-021`）。
- ⇒ **取舍**：竖排档 = 属性表（U/R/Tu/Tr）+ `vert` 调用 + 对齐语义翻转（右起）+ 字体能力检测；
  **不做**旋转近似、不做 `vrt2`。

### 2.4 字形地域归属

- 同一 Unicode 码位在不同地区字形不同；Noto CJK 给出两条路径：**选对应语言字体**或**给文本打语言标签**
  触发 `locl`，并直言“支持语言标注的应用**很少**”（`W3E-039`）；Source Han Sans 同机制（`W3E-041`），
  语言专用 OTF 是“单语言默认 + 其余靠标注”的部署形态（`W3E-040`）；Google Fonts 命名有 JP/KR/SC/TC/HK
  五地域后缀（`W3E-042`）。
- 微软字体自带 `dlng`（雅黑 `Hans`、正黑 `Bopo`,`Hant`）与代码页（936/950）（`W3E-043/044`）。
- IVD/UTS#37 为变体序列提供登记册，版本按发布日期标识且**不可变**（`W3E-037/038`）。
- clreq 的对应建议：按**地区**而非**繁简**区分排版规则（`W3E-010`）。
- ⇒ **取舍**：FontEntry 带“默认语言（dlng）+ 族名地域后缀”；文本层显式保存 locale 并传给整形器
  （决定 `locl`）；SVG/IVS 只做可查，不做编辑。

### 2.5 输入法候选窗惯例（可直接对齐的字段与默认值）

| 维度 | 惯例 | 锚 |

### 2.6 手机端与平台契约

- **Android**：候选视图固定位于软键盘之上（`W3E-060`，source）；UI 过大时提供 fullscreen 输入面板降级
  （`W3E-061`，source）。
- **iOS**：自绘键盘高度默认匹配系统键盘、**宽度由系统强制=屏宽**（只有高度可调）（`W3E-062`）；
  `secureTextEntry` 字段出现时系统替换回系统键盘（`W3E-063`）。
- **Windows**：IMM 的职责是“创建与管理 IME 窗口”（`W3E-064`）——自绘候选窗要显式声明不走系统窗口。

## 4. 坑与反例（负面留档）

1. **“竖排=整体旋转”是错的**：Tu/Tr 类要换字形（`W3E-023`），直立下仍有旋转例外（`W3E-028`），
   且 CSS 明确不用 `vrt2`（`W3E-027`）。任何“rotate(90°)”式实现都会在引号/破折号上翻车。
2. **照抄日文默认空会与中文冲突**：日文闭括号后默认二分空（`W3E-018`），中文是 1:1 密排方框
   （w3f W3F-039）——两套默认不能混用；短行放宽（`W3E-016`）也不能无门槛套到长行。
3. **`locl` 支持面窄**：Noto 自述支持语言标注的应用“很少”（`W3E-039`）——把字形地域正确性
   完全押在 `locl` 上是单点依赖；字体选择是更稳的路径。
