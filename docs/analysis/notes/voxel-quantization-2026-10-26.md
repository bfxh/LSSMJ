# 高斯体素化的三档表示：三元 / u8 / u16（2026-10-26）

结论先行：**u16 定点是「近似同面 + 内存 1/2」；要「更快的粗壳」才用三元（9–12×）。**

## 1. 三元（`voxel/voxel/ternary.rs`，2 bit/体素）

`TritField` = 每个体素被几个高斯覆盖的饱和计数（0/1/2）。67.6k 高斯、grid 256、24 线程：

| 场景 | f32 | 三元 | 倍数 | trit≥2 体素 | f32 等值面 |
|---|---:|---:|---:|---:|---:|
| scene01 | 325 ms | 27 ms | 12.2× | 277,698 | 6,438 |
| scene02 | 274 ms | 29 ms | 9.3× | 460,256 | 9,392 |
| scene03 | 304 ms | 28 ms | 11.0× | 181,519 | 2,775 |
| scene04 | 267 ms | 25 ms | 10.8× | 439,402 | 10,510 |

四场景 `surf_f32_only = 0`：三元场**包含** f32 等值面，但大 30–45 倍，IoU 0.015–0.023。

收紧核（`voxelize_ternary_with(..., m_cut)`，18=3σ → 0.25=0.5σ）救不回来：
面召回 1.00 → 0.32，IoU 最高 0.153。**计数与质量不是同一个量。**

## 2. u8 定点（`voxel/voxel/quant.rs`，1 B/体素）

`q = round(opacity·exp(-½m)·scale)`，饱和累加，`scale = 204/iso`（iso 落在 204/255）。

体素级 IoU 0.79–0.92 看着不错，但**网格体积小 31–38%**：u8 的步长 `iso/204` 让每个高斯
贡献在低端被截断，30 层叠加后系统性少算质量（`observed` 2233 → 1903，−15%）。

## 3. u16 定点（同一内核，`voxelize_quant::<u16>`）

CLI 入口：`gauss2mesh convert in.ply --grid 256 --iso 15 --quant16`（可选 `--quant-scale S` 跳过标定）。

**定标规则**：不能只看 iso。饱和会把内部体素夹平，改变等值面附近的插值（实测体积 +11% ~ −26%），
所以先用 n/2 探针取峰值密度上界，按 `scale = 60000 / 峰值` 定标。

| 场景 | f32 顶点/体积 | u16 顶点/体积 | IoU | 体积差 |
|---|---|---|---:|---:|
| scene01 | 4990 / 0.5086 | 4978 / 0.4979 | 0.997 | −2.1% |
| scene02 | 7536 / 0.1395 | 7517 / 0.1371 | 0.997 | −1.7% |
| scene03 | 2145 / 0.7066 | 2131 / 0.6867 | 0.994 | −2.8% |
| scene04 | 8190 / 0.2023 | 8153 / 0.1997 | 0.995 | −1.3% |

**性能实话**：f32 325–346 ms；u16 自动定标 426–555 ms。splat 266 ms（标量核，无 AVX2）
+ `to_field` 176 ms（转回 f32 场才能提网格）。所以当前 u16 换到的是**内存**（33 MB vs 67 MB），
不是速度。变速度收益需要：quant 核加 SIMD + mesher 直接吃 u16。

## 判据

- `tests/ternary_parity.rs`：并行 == 单线程**逐位**相同；单高斯覆盖自身体素。
- `tests/quant_parity.rs`：并行 == 单线程**逐字节**相同。
- 报告必须同时给：体素数、IoU、**顶点数、体积**、耗时、内存。只给 IoU 会把 u8 的 −31% 体积藏起来。

## 4. GPU 内核的默认策略（2026-10-26）

**前提澄清**：`conv-core` 没有任何 CUDA/cuBLAS/cuDNN 依赖，GPU 路径就是自研 wgpu/WGSL
（`jfa.wgsl` 距离场、`gsn.wgsl` Surface Nets、`mesh_sdf.wgsl`）。所以「用我们的内核」= 让这条路径默认生效，
而不是切掉某个英伟达专有实现。

**默认改为 auto**（`--gpu` 强制、`--no-gpu` 强制关）：

| 场景 | CPU | GPU | 结论 |
|---|---:|---:|---|
| 单文件 256³ | 379–383 ms | 652–690 ms | CPU（GPU init 446–450 ms 摊不平） |
| 批量 4×256³ | 3344 ms | 2810–2854 ms | **GPU（1.19×）** |
| `--gpu-mesh` 256³ | 网格 44 ms | 1155 ms 总计 | 仍 opt-in（慢一个量级） |

GPU splat 本身是 176–181 ms vs CPU 约 315 ms（**1.7×**），差距全在设备初始化。
规则：**批量 ≥2 文件或 grid ≥512 → GPU**；否则 CPU。`try_headless_device_sized(need)` 只按本次
实际缓冲申请 limits，不再一律要 512 MB 绑定。

### 4.1 512³ dense GPU 已验证（2026-10-26）

`cargo test --release --test gpu_512_probe -- --ignored --nocapture --test-threads=1` 实跑通过：

| 项 | 读数 |
|---|---|
| surfel 512³（60k 高斯，seal） | 体素化 1297–1385 ms，CPU 网格 698–722 ms |
| 网格 | 2,384,164 三角形，体积 **1.76962**（期望 1.77±0.01），χ=2，分量 1 |
| 体素 | observed 5,400,759，sealed 63,968,156 |
| density 512³ GPU | 按设计拒绝：`GPU splat job 总数溢出 u32` |

CLI 端到端（scene01 67.6k，`--grid 512 --mode surfel`，auto 选 GPU）：init 414 ms + 体素化 2529.6 ms +
网格 517.5 ms = **3528.3 ms**，84,189 顶点 / 171,268 三角形。

### 4.2 512³ density 的 auto iso：已按实测规律换算（体积仍与 256³ 不同）

实测 f32 的 auto iso 随分辨率变化（scene01，同一份点云）：

| grid | iso | 相对上一档 |
|---|---:|---:|
| 128 | 117.523 | — |
| 256 | 29.386 | ÷4.00 |
| 512 | 7.469 | ÷3.94 |

⇒ **iso ∝ n⁻²**（不是 h³）。稀疏路径的 256³ 探针现在按 `(probe_n/n)²` 换算：
scene01 512³ 得 iso=7.347（实测 7.469，差 1.7%），**不再报「没有生成三角形」**，
体素化 670.8 ms、总计 726 ms。

**但体积不等于 256³**：scene01 0.25505 vs 0.50864、scene03 0.35819 vs 0.70657（约 1/2）。
原因是 `iso = 0.65 × p99.9` 这个启发式本身随分辨率漂移——p99.9 在更细网格上分布不同，
换算能保证「非空且量级正确」，但保证不了「同一张面」。要同面必须显式 `--iso`。
真正的修法是**两遍稀疏**：先在活跃块上以目标分辨率统计 p99.9，再定 iso。


density 在 >256³ 走稀疏 CPU，auto iso 取自 **n/2 探针**（256³）。但密度是「每体素质量」，
换分辨率后阈值不等价：scene01 的 256³ iso=29.39，直接拿到 512³ 就是 **0 体素**。
实测 512³ 等效阈值约 6（iso=5.0 → 体积 0.762；iso=7.0 → 0.308；256³ 基线 0.509）。

现在报错会带上 iso 与原因，并提示显式传 `--iso`；**换算规则未定，不做猜测性修复**。

## 5. quant 核 SIMD 与「Surface Nets 直读 u16」的实测结论（2026-10-26）

### 5.1 AVX2 quant 行内核：正确，但在 256³ 没有收益

`avx2::quant_row` 与标量 `splat_quant_chunk` **逐位一致**（单测 `avx2_quant_row_matches_scalar_bitwise`，
u8 与 u16 各测一遍）。但配对 A/B（同场景交替 5 轮，只计 splat）：

| 轮 | AVX2 开 | AVX2 关 | 谁快 |
|---|---:|---:|---|
| 1 | 416.7 ms | 416.3 ms | 平 |
| 2 | 436.4 ms | 372.7 ms | 关 |
| 3 | 426.5 ms | 457.5 ms | 开 |
| 4 | 441.7 ms | 487.2 ms | 开 |
| 5 | 306.1 ms | 294.2 ms | 关 |

5 轮 2:2、1 平，中位数 开 426.5 vs 关 416.3 ⇒ **没有收益，略差**。

原因两条：3σ 核在 256³ 下 x 跨度只有 6–10 格，8 lane 向量体几乎不触发，反而白付建常量开销；
且 splat 本身是**写带宽受限**（u16 场 33 MB、f32 67 MB），不是 maha 计算受限。
**处理**：加门限 `span ≥ 15` 才走 SIMD，256³ 恒走标量 ⇒ 行为与 CHG-Q 完全一致
（四场景 v/t/vol 逐位复现：4978/10076/0.4979、7517/15344/0.1371、2131/4248/0.6867、8153/16756/0.1997）。

### 5.2 直读 u16 网格：快 2.4×，但差 21% 体积，不达同面判据（已回退）

用 `repr(transparent)` 的 i16 偏置场（阈值落在 0）让 `fast-surface-nets` 直接吃 2 字节场：

- 转换+网格 **91–104 ms**，对照 `to_field` + 网格约 220 ms ⇒ **约 2.4×**。
- 顶点/三角形与参照**完全一致**（4978 / 10076），χ 也一致（1）。
- 但体积 **0.6052 vs 0.4979（+21%）**。

根因：f32 路径把未知区写成 `outside = q999`，而 `iso = 0.65·q999` ⇒ `outside > iso`。
16 位偏置场能表示的上界只有 `iso`（q=0 时），**装不下 `outside`**，所以近表面外侧的插值必然偏移。
要真正直读，得自己写 Surface Nets 并把 `outside` 作为参数传入，而不是靠 16 位编码。

**结论**：按「不降低验收标准」处理 —— 代码已回退，不进 CLI。留作后续自研 mesher 的输入证据。

### 4.3 两遍稀疏实测：块采样有偏，已回退（2026-10-26）

**做法**：先 `splat_raw` 只做 splat，在活跃块的**核心区**（排除 halo）统计正密度 p99.9，
再按 `iso = 0.65 × p99.9` 做第二遍。

**结果**（scene01 / scene03，512³）：

| 场景 | 活跃块 p99.9 | 全网格 p99.9 | 得到 iso | 体积 | 对照（n⁻² 换算） |
|---|---:|---:|---:|---:|---:|
| scene01 | 14.77 | 11.49 | 9.60 | **0.0538** | 0.25505 |
| scene03 | 30.27 | — | 19.68 | 0.0624 | 0.35819 |

**比换算方案更差**。原因：活跃块只占全网格 **0.3–0.4%**，而且正是表面附近密度高的区域，
p99.9 系统性偏高 ⇒ iso 偏高 ⇒ 面被削小。

**结论**：已回退。`0.65 × p99.9(全网格)` 这个启发式本身随分辨率漂移（采样点数变了），
块采样不能替代全网格统计。要跨分辨率同面，**iso 必须用绝对（世界）单位**，
或者给 splat 加体素体积归一化让密度与分辨率无关——两者都会改变默认哈希，需单独迁移。

### 4.4 更正：「512³ 体积约为 256³ 一半」是**未封闭壳**的假象（2026-10-26）

同口径复测（都开 `--largest-component`）：

| 场景 | 256³ | 512³ |
|---|---|---|
| scene01 | 0.26242，χ=0，4440 三角形 | 0.12062，**χ=−6**，16372 三角形 |
| scene03 | 0.44814，χ=2 | 0.21206，**χ=−7** |

512³ 的 χ 为负、三角形数是 256³ 的 ~2 倍 ⇒ 输出是**双面壳**，不是闭合体。
非闭合网格的「有符号体积」本来就没有定义，所以 §4.2 里「体积减半」的对比**不成立**。

**根因**（读 `seal_blocks` 确认）：它只遍历 `blocks.active()`，且泛洪传播限制在 `class[nb]==2`（活跃块）。
512³ 稀疏下活跃块只有 0.3–0.4%（表面附近），**内部体素从未被标记、也从未被填成 −outside**
⇒ `sealed_interior=0` ⇒ 壳。

**这不是 iso 的问题**，是稀疏封洞只覆盖表面块的问题。修法（未做）：
让封洞与网格化都感知「内部块」——块级泛洪判定哪些空块被围住，把它们当作实心（−outside），
且不必真的分配内存（在 mesh 阶段把缺失邻居视作内部即可）。

**因此**：`iso ∝ n⁻²` 的换算是否「同面」目前**无法用体积判断**，需要先修封洞再用 χ/三角形数/体积三联指标复验。

### 4.5 决定性实验：用粗场符号封洞能闭合，但体积跟随**粗分辨率表面**

给 `post_block` 传粗场（`blocks.coarse()`，128³ 稠密场）与 `ratio=(cn-1)/(n-1)`，
未知体素按粗场符号写 ±outside。结果：

| 场景 | 512³ 回退前（壳） | 512³ 粗场符号封洞 | 256³ 基线 |
|---|---|---|---|
| scene01 | 0.12062，χ=−6 | **1.81742，χ=1** | 0.26242，χ=0 |
| scene03 | 0.21206，χ=−7 | **2.82621，χ=3** | 0.44814，χ=2 |

网格**闭合了**（χ 转正、单分量），但体积是基线的 **7×**——因为未知区的内外跟着**128³ 粗表面**走，
而粗表面本身与 512³ 细表面不是同一张。

**结论（决定性）**：跨分辨率不一致在**场本身**，不在封洞、不在 iso 换算。
粗、中、细三档的等值面互不相同，任何「用另一档的符号/分位数」补救都只会把面换成那一档的。
代码已回退，只保留本记录。

**唯一正确修法**：让 splat 归一化体素体积（`density *= h³` 或等价），使密度与分辨率无关；
或让 iso 以世界绝对单位给出并只在内部换算。两者都改变默认输出哈希 `b72fbdaae0aa6e88`，
需先定迁移方案与回滚点，不能静默改。

### 4.6 opt-in 归一化的前提检验：128 vs 256（都稠密、都闭合）

要判断「把密度按 h² 归一化 + 固定 iso」能否跨分辨率同面，先做一次**没有壳干扰**的对照：

| 场景 | 128³（h=0.1664） | 256³（h=0.08319） | 比值 |
|---|---|---|---|
| scene01 | 0.70736，χ=3，1 分量 | 0.26242，χ=0，1 分量 | **2.7×** |
| scene03 | 1.88872，χ=4，1 分量 | 0.44814，χ=2，1 分量 | **4.2×** |

两档都走稠密路径、χ≥0、单分量，**不存在壳的干扰**，体积仍差 2.7–4.2 倍。

关键算术：auto iso 之比 117.523/29.386 = **4.00**，正好等于 `(h₁₂₈/h₂₅₆)² = 4.00`。
也就是说 **iso ∝ h² 精确成立**，按 h² 归一化后两档的归一化阈值都是 **≈4245**；
但同一个归一化阈值给出的体积仍是 0.707 vs 0.262。

⇒ **归一化能让「阈值口径」一致，但换不来同一张面**：密度场的**局部**数值并不按 h² 缩放，
只有它的 99.9 分位按 h² 缩放。残差来自 3σ 截断与格点采样（`kernel_clamp_cells`）在粗网格下的差异。

**因此 opt-in 开关不能兑现「同面」承诺**，暂时不发。要真正解决，得让 splat 本身与分辨率无关
（对核做体素内积分，而不是点采样 + 3σ 硬截断），这是另一层改动。

### 4.7 opt-in `--kernel-clamp-world`：跨分辨率差异 2.7×/4.2× → 1.47×/1.59×

**根因定位**（读代码）：`prepare_density` 里 `min_var = (kernel_clamp_cells × grid.h)²`，
默认 `kernel_clamp_cells = 0.75`。也就是说**核的标准差下限是「按格数」算的**——
粗网格上同一个 0.75 格对应更大的世界尺度，核被系统性撑胖 ⇒ 密度偏高 ⇒ 等值面变大。
这正是「iso ∝ h² 成立、但面不跟着变」的来源。

**开关**：`--kernel-clamp-world <σ>` 用世界单位给同一 σ（opt-in，默认仍是按格）。
各场景取自己 256³ 的等效 σ（scene01 0.0624、scene03 0.0943）：

| 场景 | 128³ | 256³ | 比值 | 改前比值 |
|---|---|---|---|---|
| scene01 | 0.17942，χ=5 | 0.26361，χ=0 | **1.47×** | 2.70× |
| scene03 | 0.27703，χ=1 | 0.43944，χ=2 | **1.59×** | 4.21× |

**结论**：按世界单位夹核能消掉一大半系统性差异，但**没有完全收敛**——128³ 本身就是粗网格，
细结构表示不了，剩余差距里有一部分是真实的离散化误差。

**默认行为未变**：哈希仍是 `b72fbdaae0aa6e88`；`gauss_leg` 9、`gsn_gpu` 2、`quant_parity` 1 全过。

### 4.8 「1.5× 里离散化占多少」——用解析球定量

**方法**：`demo sphere`（半径 0.75，解析体积 **1.76715**），density 模式，96/128/192/256 四档。
球是厚实、光滑的目标，能把「数值口径的离散化误差」单独量出来。

| grid | 体积 | 相对解析误差 |
|---|---|---|
| 96 | 1.83064 | +3.59% |
| 128 | 1.81553 | +2.74% |
| 192 | 1.80328 | +2.04% |
| 256 | 1.79683 | +1.68% |

- **128³ / 256³ = 1.0104 ⇒ 数值口径的跨分辨率差异只有约 1%**。
- 绝对误差从 3.59% 单调收敛到 1.68%（`iso = 0.65×p99.9` 的阈值偏高，随网格细化收敛），这是**估值偏差**，不是分辨率差。

**对照场景**（同世界 σ，§4.7）：scene01 128/256 = 1.47×、scene03 = 1.59×。

⇒ **结论**：剩下的 1.5× 里，**数值离散化只占约 1%**；其余约 45–60% 是 **128³ 表示不了场景里的薄结构**
（桌面、椅腿这类厚度接近或小于体素的部件在粗网格上直接消失），属于几何信息丢失，
不是 splat 或 iso 的估值 bug。

**可推论**：想让 128³ 与 256³ 同面，靠改阈值/归一化都没用——必须提高分辨率，
或者对薄结构做专门的抗混叠（例如按体素内覆盖率加权），后者会改变默认语义。

### 4.9 质量守恒夹核：在 auto-iso 下是空操作（已回退）

**想法**：夹核把薄核撑胖会让峰值变淡，薄结构因此消失。按 `√(detΣ_原 / detΣ_夹)` 反向补偿幅度，
理论上可保住总质量。

**实测**：

| 场景 | 默认 | `--mass-preserving-clamp` |
|---|---|---|
| scene01 48³ | 6.02336 | 6.02339 |
| scene01 128³ | 0.70736 | 0.70736 |
| scene01 256³ | 0.26241 | 0.26241 |
| 球 128³/256³ | 1.81553 / 1.79683 | 完全相同 |

**为什么是空操作**：补偿是对所有高斯**近似等比**的缩放，而 `iso = 0.65 × p99.9` 会跟着一起缩放
⇒ 等值面不变。只有在**固定 iso** 下，这种补偿才会改变结果。

**结论**：auto-iso 与「保质量」互相抵消，这条路不通，代码已回退（默认哈希 `b72fbdaae0aa6e88` 未变）。

**到此为止的定论**：在 `iso = 0.65×p99.9` 这套自定阈值下，128³ 与 256³ 不可能同面——
差的那 45–60% 是粗网格的几何信息丢失（§4.8 用解析球证明数值离散化只占约 1%）。
要同面只有两条路：**固定绝对 iso + 体素体积归一化**（会改默认语义），或**直接用足够高的分辨率**。

### 4.10 固化：`--kernel-clamp-ref <N>` 按参考网格折算核宽

§4.7 的 `--kernel-clamp-world <σ>` 要按场景手算 σ（scene01 0.0624、scene03 0.0943），不便进管线。
新增 `--kernel-clamp-ref N`：内部按 `h_ref = h_cur × (n−1−2p)/(N−1−2p)` 反推参考网格的格距，
再用 `0.75 × h_ref` 定核下限——**同一参考值在任何 grid 上得到同一世界 σ**，无需手算。

等价性实测：

| 场景 | 256³ `--kernel-clamp-ref 256` | 256³ 默认 | 128³ ref256 | 128³ 手算 world σ |
|---|---|---|---|---|
| scene01 | 0.26242 | **0.26242** | 0.17204 | 0.17942 |
| scene03 | 0.44814 | **0.44814** | 0.27891 | 0.27703 |

- 在参考网格上与默认**逐位相同**（预期：σ 相同）；
- 在 128³ 复现手算 σ 的效果（差 4% / 0.7%，因为手算用了四舍五入的 σ）。
- 跨分辨率比：scene01 1.53×、scene03 1.61×，与 §4.7 的 1.47×/1.59× 一致。

**管线用法**：drift 的网格命令统一加 `--kernel-clamp-ref 256`，128/256/512 共享同一核宽。
默认路径不受影响（哈希 `b72fbdaae0aa6e88` 未变）。

### 4.11 提速实测：封洞是最大单点开销，改扫描线后 −26%

**先算账**（scene01，256³，单文件）：

| 阶段 | 耗时 |
|---|---:|
| f32 体素化（含封洞） | 318–331 ms |
| f32 体素化（`--hollow`，不封洞） | 205 ms |
| ⇒ **封洞本身** | **≈ 126 ms（38%）** |
| u16 splat（不含转换/封洞） | 264–270 ms |

**所以 u16 直读网格即使做成也不划算**：端到端 = 266（splat）+ 44（网格）+ 126（封洞）≈ **436 ms**，
而 f32 是 331 + 44 ≈ **375 ms**。之前那个「2.4×」只是 `to_field` 单阶段，不是端到端。

**真正的瓶颈是封洞**：`seal_unknown` 用逐体素 BFS（`VecDeque` + 每体素 6 邻居）。
改成**扫描线填充**（每种子沿 x 扩成一段，只把上下左右 4 个邻行里重叠的未知段入栈），
入栈次数从 O(体素) 降到 O(段)。

| 指标 | 改前 | 改后 |
|---|---:|---:|
| 体素化（含封洞） | 330.9 ms | **242.6–246.5 ms** |
| 默认哈希 | `b72fbdaae0aa6e88` | **不变** |
| 四场景体积 | 0.26242 / 0.04521 / 0.44814 / 0.11293 | **完全相同** |

封洞语义不变（同一连通分量），所以输出逐位一致；**−86 ms，约 1.35×**。
`gauss_leg` 9、`gsn_gpu` 2、`quant_parity` 1 全过。

### 4.12 splat 的瓶颈归因：不是 exp（配对 A/B 实测）

想知道 splat（`--hollow` 口径 ≈205 ms）里 `exp` 占多少，用两个二进制交替跑 5 轮配对：

| 轮 | 正常（含 exp） | 去掉 exp | 谁快 |
|---|---:|---:|---|
| 1 | 366.5 ms | 303.2 ms | 无 exp |
| 2 | 343.1 ms | 335.3 ms | 无 exp |
| 3 | 371.8 ms | 339.9 ms | 无 exp |
| 4 | 366.7 ms | 332.9 ms | 无 exp |
| 5 | 302.0 ms | 347.7 ms | 含 exp |

中位数 **366.5 vs 335.3 ⇒ 去掉 exp 只快约 8%**（4/5 轮胜）。

**结论**：
- `exp` 不是瓶颈。splat 的开销主要在**遍历每个高斯的 3σ bbox 并逐体素算 Mahalanobis + 写场**，
  而 `m > 18` 的提前退出已经把 exp 限制在椭球内部。
- 这也解释了 u16 为什么更慢：它是标量核，算术占主导，省下的写带宽被算术吃掉。
- **精确算术下没有剩余提速空间**：8% 的 exp 优化还要改数值（近似 exp），不划算。

**所以 splat 提速的可行方向只剩改数值语义**（近似 exp / 更低精度累积 / 子采样），
都必须 opt-in 且需要重新验证网格一致性。当前判断：**不值得做**。
