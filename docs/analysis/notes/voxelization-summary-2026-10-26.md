# 3DGS 体素化：经验总结（2026-10-26）

> 入口文档。把 `voxel-quantization-2026-10-26.md`（实验流水）与多轮失败记录压成一份
> 「现在该怎么做、哪些别再试」。所有数字均为本机实测（RTX 4060 Ti / 24 线程 / 67.6k 高斯）。

---

## 0. 一句话

默认路径（auto-iso + 核宽随 h）在同一分辨率下稳定且快；**跨分辨率要同面，唯一有效的手法是
`--kernel-clamp-ref N` 把核宽钉在世界单位 + 显式固定 `--iso`**。它把 512³ 从「双面壳」
（χ=−39、25 分量）救成基本闭合（χ=5、5 分量），但 128/256/512 仍不是逐位同一张面，
剩余差异是真实的几何信息量，不是参数没调对。

---

## 1. 口径（读代码前先记住这几条）

| 概念 | 含义 |
|---|---|
| `density` | 每个高斯按 `α·exp(−½ Mahalanobis)` 累加到体素，阈值化后取等值面；**无符号** |
| `surfel` | 以最薄轴为法线做 TSDF 融合，需要法线/2DGS 资产 |
| `iso` | 默认 `0.65 × 正密度 p99.9`；`--iso` 给绝对值 |
| 核宽下限 | `kernel_clamp_cells(0.75) × h`，**随分辨率漂移**——这是跨分辨率不一致的主因 |
| `seal` | 从域边界泛洪标外部，被围住的未知区填内部；density 下常是**空操作** |
| 稀疏路径 | `grid > 256` 的 density 走它；只算候选块 + 1 格 halo，512³ 的 iso 由半分辨率探针换算 |
| GPU | auto：批量 ≥2 文件或 `grid≥512 且 surfel`；单文件 256³ 走 CPU（设备初始化摊不平） |

**关键不变量**：默认单文件 256³ `--largest-component` 的输出哈希 = `b72fbdaae0aa6e88`。
任何改动后都要复验它。

## 2. 性能账（256³，scene01）

| 阶段 | 耗时 | 备注 |
|---|---:|---|
| splat（`--hollow` 口径） | ~205 ms | 遍历每个高斯 3σ bbox + Mahalanobis + 写场 |
| 封洞（扫描线，2026-10-26 改） | ~39 ms | 改前逐体素 BFS ≈126 ms |
| 体素化合计（含封洞） | **242.6–246.5 ms** | 改前 330.9 ms（1.35×） |
| Surface Nets 网格 | ~44 ms | GPU 网格 1155 ms，默认不用 |
| 端到端单文件 | ~290–305 ms | |

其它实测：

| 场景 | 读数 |
|---|---|
| GPU 单文件 256³ | 652–690 ms（其中设备初始化 446–450 ms；GPU splat 本身 176–181 ms vs CPU ~315 ms） |
| GPU 批量 4×256³ | 2810–2854 ms vs CPU 3344 ms（1.19×） |
| 512³ surfel dense GPU | 体素化 1297–1385 ms，体积 1.76962、χ=2、单分量 |
| 512³ density | 稀疏 CPU，~410–440 ms（含探针） |
| u16 定点 splat | 264–270 ms（**比 f32 慢**），峰值内存 33 MB vs 67 MB |
| u16 直读 mesher 端到端 | ≈436 ms（splat 266 + 网格 44 + 封洞 126）vs f32 ≈375 ms ⇒ 否决 |

**splat 瓶颈归因**：去掉 `exp` 只快约 8%（5 轮配对中位数 366.5 vs 335.3）。开销在 bbox 遍历
与 Mahalanobis，不在 `exp`。精确算术下没有剩余提速空间。

## 3. 精度 / 同面

### 3.1 三种量化口径

| 口径 | 同面程度 | 价值 |
|---|---|---|
| 三元 2-bit 计数 | 粗壳，不同面 | 极省内存/带宽的粗定位 |
| u8 | 近似同面（IoU 0.994–0.997） | 省内存 |
| u16 定点 | 近似同面（IoU 0.994–0.997，体积偏差 ~1%） | 省内存，不提速 |

### 3.2 跨分辨率（scene01 / scene03，体积）

| 配置 | 128³ | 256³ | 512³ | 512/128 |
|---|---:|---:|---:|---:|
| 默认（2026-10-26 迁移前） | 1.05566 | 0.50864 | 0.25505（χ=−39，25 分量） | 0.24 |
| **默认（迁移后：>256³ 钉核宽）** | 1.05566 | 0.50864 | **0.72455（χ=5，5 分量）** | 0.69 |
| 迁移后（scene03） | 2.00791 | 0.70657 | **1.17873（χ=17，10 分量）** | 0.59 |
| **pinned**（`--kernel-clamp-ref 256` + 显式 iso） | 0.29814 | 0.50864 | **0.72455**（χ=5，5 分量） | 2.43 |
| **pinned**（scene03） | 0.38344 | 0.70657 | 1.17873 | 3.08 |

- 默认配置下 512³ 的 iso 由探针 `× (probe_n/n)²` 换算，512 体积约为 256 的一半，且拓扑是壳。
- pinned 后密度近似分辨率无关（128 的 auto iso = 28.806 vs 256 的 29.386，差 2%），
  显式 iso 才有意义；512 的稀疏 auto-iso 也不再乘 `n⁻²`。
- pinned 的体积序列单调（0.30 → 0.51 → 0.72），相邻档差 1.42–1.67×；**仍不是同一张面**。

### 3.3 解析球基线

| 网格 | 体积 | 误差 |
|---:|---:|---:|
| 96³ | 1.83064 | +3.59% |
| 128³ | 1.81553 | +2.74% |
| 192³ | 1.80328 | +2.05% |
| 256³ | 1.79683 | +1.68% |

真值 1.76715；128/256 = **1.0104** ⇒ 光滑闭合体的数值离散化只有约 1%。
所以真实场景那 1.4–3× 的差**不是**数值误差，是粗网格丢掉薄结构。

## 4. 已证伪的方向（别再试）

| # | 方案 | 结果 | 落位 |
|---|---|---|---|
| 1 | 两遍稀疏（活跃块子集求 p99.9） | 体积 0.0538，差 4–5× | `9fdee9a` |
| 2 | 借 128³ 粗场符号封洞 | 闭合了但体积 ≈256³ 的 7× | `47bfa02` |
| 3 | 质量守恒夹核 | 逐位空操作 | notes §4.9 |
| 4 | u16 直读 mesher | 端到端 436 > 375 ms，体积 0.6052 vs 0.4979 | notes §4.10 |
| 5 | 近似 exp / 去掉 exp | 只快 8%，且改数值 | notes §4.12 |
| 6 | 「修 512³ 稀疏封洞」 | `seal` 与 `--hollow` 输出**完全相同**，封洞是空操作 | notes §4.13 |
| 7 | 加大候选块 margin（0→2/4/8） | 块数 128→936，体积与 χ 不变 | notes §4.13 |
| 8 | 只做密度归一化（`--density-norm`）不钉核宽 | 固定 iso 下 512 仍 χ=−27/28 分量（还是壳） | 本文 §3.2 |
| 9 | 体素内积分 splat（`--splat-integrate`，Σ+h²/12） | iso 反随分辨率升 1.6×/档；固定 iso 切 128³ 只剩 0.00493。尖峰场没有尺度不变的点值 | notes §4.15 |

**共同教训**：不一致在「场」本身（核宽口径 + 几何信息量），不在封洞、不在块覆盖、不在 iso 换算公式。

## 5. 推荐配方

```bash
# 默认：单文件 256³（>256³ 的 density 会自动把核宽钉在参考 256³ 世界尺度）
gauss2mesh convert scene.ply --grid 256 --largest-component
gauss2mesh convert scene.ply --grid 512 --largest-component   # 默认已是实心体，无需额外开关

# 跨分辨率对齐（opt-in）：核宽与阈值都钉在 256³
gauss2mesh convert scene.ply --grid 128 --kernel-clamp-ref 256 --iso 29.38631
gauss2mesh convert scene.ply --grid 256 --kernel-clamp-ref 256 --iso 29.38631
gauss2mesh convert scene.ply --grid 512 --kernel-clamp-ref 256 --iso 29.38631

# 只想保留默认核宽但要固定阈值（较弱，拓扑仍可能不闭合）
gauss2mesh convert scene.ply --grid 512 --density-norm 256 --iso 29.38631

# 批量：默认 auto 会选 GPU（设备初始化只付一次）
gauss2mesh convert a.ply b.ply c.ply d.ply --grid 256 --out-dir out/
```

`--iso` 的取法：在参考网格（默认 256³）上跑一次 auto，读日志里的 `iso=`，之后所有分辨率复用。

## 7. 未解决 / 未验证

1. **128/256/512 仍不是同一张面**：pinned 后相邻档仍差 1.42–1.67×，属薄结构随分辨率增益。
   要真正同面，只能提高分辨率或换连续表示（隐式场），不是调阈值。
2. **512³ density 不走 GPU**：job 表会溢出 u32，是设计拒绝，不是 bug。
3. **`--density-norm` 单独使用**：只修正密度幅度，不修正核宽，512 仍是壳；保留作为 A/B 工具，
   不作为推荐路径。
4. **`--bins3d` 与 `--density-norm` 不兼容**（tile 路径未归一化，显式报错）。
5. **GPU 内核未实现 density-norm**：显式选 GPU 时会降级到 CPU 并在日志说明。
6. **`--splat-integrate` 是实验开关**：物理更正确但分辨率相关，**不要用于生产**（见 §4 第 9 条）。
7. **128/256 之间仍有 2.08×**：默认口径下 128 的核宽下限按格算会撑胖；要跨档一致请显式
   `--kernel-clamp-ref 256 --iso <256³ 的 iso>`（得到 0.298 / 0.509 / 0.725）。
