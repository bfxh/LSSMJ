## TL;DR（10 条，每条带锚）

1. **蒙皮的规范式只有一个乘法**：`jointMatrix(j) = globalTransformOfJointNode(j) × inverseBindMatrixForJoint(j)`
   （`W10A-001`）；glTF 用 skin 对象 + 关节层级 + 顶点属性表达 LBS，且**省略** Bind Shape Matrix
   （预乘进网格或逆绑定矩阵，`W10A-003/002`）。**蒙皮动画=驱动关节节点**，蒙皮只是消费关节变换的渲染步骤（`W10A-007`）——
   这条边界决定了 LSSMJ 的动画系统只写节点/关节变换，蒙皮留在渲染侧。
2. **播放语义的边界条件比插值本身更容易错**：采样输入之外必须钳制到最近端点（`W10A-005`）；STEP 是"不插值"
   而非"权重为 0 的线性"（`W10A-008`）；非线性时间输入（time warp）在 glTF 里**不可表示**，导出期必须采样成线性
   （`W10A-006`）。LSSMJ 的导入契约照此把非线性时间烘焙掉，运行时不实现 time warp 求值器。
3. **权重不足 1 的回落是混合正确性的边界**：three.js 用 `original × (1 − cumulativeWeight)` 把结果拉回绑定前原值
   （`W10A-012`），并用双缓冲累加下标（`W10A-010`）+ "原值/常规/加性"三段固定缓冲布局（`W10A-011`）实现零分配求值。
   LSSMJ 必须显式定义回落语义并写成金样——这是"半权重时的姿态"最容易出不一致的地方。
4. **GPU 蒙皮是"骨骼矩阵连续数组 + 骨架纹理"两段结构**：每骨 16 浮点、每矩阵 4 个 RGBA 像素，纹理边长按骨骼数分档
   （8×8→16 骨、64×64→1024 骨，`W10A-013/014`）；bindMode 分 Attached/Detached，后者用于多网格共享一副骨架
   （`W10A-015`）。LSSMJ 的骨架缓冲照此设计，尺寸换算进单测。
5. **混合模型有两条成熟形态，LSSMJ 都应支持且共用一套节点语义**：Bevy 是显式 **DAG**（每帧自底向上求值），
   节点只有 blend/add/clip 三类，blend 归一化子权重、add 明确不归一（`W10A-018/019/020`）；
   Godot 是"混合图 + 状态机节点"（`W10A-059/062/063`）；Unity 的混合树按 Blend Parameter 连续混合，
   并要求被混动作"性质与节奏相似"（`W10A-037/038`）。
6. **状态机的最小构件是"入口 + 状态 + 转移（时长+条件）+ 子状态机"**（`W10A-045/037`）；
   UE 另给两个结构性原语：**conduit**（1 对多/多对多/多对一的条件汇聚，`W10A-046`）与
   **单帧最大转移次数护栏**（防同帧级联打转，`W10A-047`）。Godot 把"图资产"与"playback 游标"分成两个对象
   （`W10A-063`），跳转是 `travel(state, reset_on_teleport)`（`W10A-032`），转移曲线挂在 Transition 对象上（`W10A-033`）。
7. **过渡/叠加/分层的三件套要分开建模**：交叉淡入淡出最小实现=旧动画权重按 `1/duration` 线性衰减（`W10A-023`）；
   加性是独立节点语义（`W10A-020/029/049`，UE 的 Apply Additive 受 LOD 阈值控制）；
   分层混合按**骨骼遮罩**定义（UE 的 Layered blend per bone：Branch Filter 或 Blend Mask，`W10A-048`）；
   质量档可加惯性化过渡（Inertialization，`W10A-050`）。
8. **IK 的默认求解器是 FABRIK，且必须规定"解算前同步"与"权重语义"**：Godot 的生产实现就叫
   `FabrikInverseKinematic`（`W10A-034`），与 Aristidou 2011 的论文互证（`W10A-069`）；
   求解前要"同步链根到动画后的最新变换"并把目标与当前姿态混合（`W10A-035`）。
   UE 把 IK 目标做成与骨骼并列的一等对象（`W10A-051`），求解器可堆叠成栈（三骨链→全身多肢，`W10A-052`）；
   Unity 的权重语义精确到"0=IK 前原始动画，1=目标"（`W10A-040`）。两骨链优先解析解（`W10A-071`），
   多骨链退到 FABRIK。
9. **根运动要按"分量 × 物理状态"分工，而不是全有或全无**：UE 由 Animation Blueprint 的 Root Motion Mode
   决定提取方式并提供 Ignore 档（`W10A-054`），且物理状态下竖直分量交重力接管（`W10A-055`）；
   Unity 的 Bake into Pose 分旋转/Y/XZ，并直接改 `Animator.gravityWeight` 决定竖直位移归谁（`W10A-042`）；
   Godot 的根运动来源是资产里的显式轨迹（`root_motion_track`，`W10A-061`），并明确"整体旋转超过 180° 用根运动"
   （`W10A-060`）。"对齐式动作"由运动变形（Motion Warping）解决（`W10A-053`）。
10. **表情/次级运动/数据驱动是三层可选能力，不能混进默认档**：表情=morph target（权重栈按 target 数紧密打包，
    `W10A-024`；名字是资产契约，`W10A-058`）；次级运动（头发/衣摆）=逐关节 stiffness/drag/gravity 的弹簧骨
    （`W10A-065`）；高级形变（肌肉）=pose space deformation（`W10A-075`）；动画数据降维=PCA 谱系（`W10A-076`）；
    数据驱动的 motion matching（`W10A-077`）与其学习式变体（`W10A-078`）列"状态机之后"的候选档
    （学习式因训练链/权重资产与"纯 Rust 可复算"纪律冲突，只作观察）。

## 1. 动画系统的最小架构（由证据推出来的分层）

```text
clip（采样）           clip 资产：通道 + 关键帧 + 三种插值 + 端点钳制      W10A-005/008
   │
graph（混合）          DAG：blend / add / clip 三类节点 + 归一化规则        W10A-018..020
   │
state（选择）          状态机：入口/状态/转移(时长+条件)/子状态机/conduit   W10A-037/045/046
   │
pose（姿态修正）       IK（FABRIK/解析两骨）+ 约束集合 + 运动变形           W10A-034/040/052/053
   │
root（位移归属）       根运动模式 + 分量烘焙 + 物理状态表                    W10A-042/054/055/061
   │
skin（渲染侧）         骨骼矩阵数组 + 骨架纹理 + bindMode                   W10A-001/013/014/015
```

六层各自可有独立门与预算：clip 采样（确定性金样）、graph（权重和为 1 / 回落语义）、state（转移上限/无死循环）、
pose（末端误差/关节极限）、root（位移不重复计账）、skin（GPU 上传尺寸与矩阵正确性）。

## 3. 重点来源短分析（6 份）

### 3.1 glTF 2.0 规范与 Khronos 教程——跨引擎的运行时契约

- 蒙皮只承诺 LBS，省略 Bind Shape Matrix，逆绑定矩阵必须 MAT4 且与 joints 同序（`W10A-003/002/004`）。
- 采样输入相对动画 t=0、范围外钳制、三种插值、非线性时间不可表示（`W10A-005/006/008`）。
- 结论：**LSSMJ 的动画资产契约以 glTF 为准**，导入期把一切非线性时间与多余绑定矩阵烘焙掉（并记账）。

### 3.2 three.js `dev` 源码——属性绑定与权重累加的参考实现

- mixer 是"某对象上的播放器"，内部双缓冲累加（`W10A-009/010`）；PropertyMixer 固定三段缓冲布局（`W10A-011`），
  权重不足 1 时向原值回落（`W10A-012`）；Skeleton 的骨骼矩阵数组与骨架纹理分档（`W10A-013/014`）；
  SkinnedMesh 的 bindMode/bindMatrix 语义（`W10A-015`）。
- 结论：**LSSMJ 的求值器照此实现"零分配 + 显式回落"**，这是动画热路径的性能与正确性基线。

### 3.3 Bevy `52c3ec0d` `bevy_animation`——类型化插值与显式 DAG

- `Animatable` trait 把插值下沉到类型，权重允许越界（`W10A-016/017`）；图是 DAG、三类节点、blend 归一/add 不归一
  （`W10A-018/019/020`）；播放器只有一张活跃表、求值器跨帧缓存（`W10A-021/022`）；过渡是权重线性衰减（`W10A-023`）；
  morph 权重栈有长度约束（`W10A-024`）。
- 结论：**LSSMJ 的动画图与类型化插值直接以 Bevy 为参照**（Rust 生态内最接近的实现），但把"过渡/状态机"做成独立层，
  不学它的临时 transition API（Bevy 自己标注 unstable，`W10A-023`）。

### 3.4 Godot `084a2caa` 源码——固定帧管线、capture 与 FABRIK

- 混合管线的固定次序：init → 预处理 → **capture** → 总权重 → 混合 → 应用 → 后处理 → 信号（`W10A-025/026`）；
  缓存有效位门控整条管线（`W10A-027`）；OneShot 双输入 + 请求枚举（`W10A-028`）；Add2 参数化叠加（`W10A-029`）；
  BlendSpace2D 用点+三角形拓扑并维护索引自洽（`W10A-030/031`）；状态机 `travel` + Transition 对象 + 交叉混合
  （`W10A-032/033`）；**FABRIK 生产实现**（`W10A-034/035`）；骨骼全局姿态脏标记备份（`W10A-036`）。
- 结论：**LSSMJ 的帧阶段次序、姿态 capture、混合空间拓扑与 IK 求解都取 Godot 为工程参照**（C++ 实现可逐段对照）。

### 3.5 Unity / Unreal 文档——状态机、分层、IK 与根运动的产品面

- Unity：转移=时长+条件（`W10A-037`）；混合树要求动作性质/节奏相似（`W10A-038`）；IK 从目标反求关节（`W10A-039`）；
  IK 权重 0/1 语义（`W10A-040`）；不可见时只更新根（`W10A-041`）；Bake into Pose 三分量 + gravityWeight（`W10A-042`）；
  Humanoid Avatar 语义骨架与 rig 约束集合（`W10A-043/044`）。
- Unreal：入口/子状态机/conduit/单帧转移上限（`W10A-045/046/047`）；layered blend per bone / additive / inertialization
  （`W10A-048/049/050`）；IK goals 一等对象 + solver stack（`W10A-051/052`）；motion warping（`W10A-053`）；
  根运动模式与物理状态（`W10A-054/055`）；notify 与 notify state（`W10A-056/057`）；morph 命名契约（`W10A-058`）。
- 结论：**产品面语义都在这里**（位移归属、IK 权重、LOD 降级、事件轨道）——LSSMJ 的验收判据直接照抄这些定义。

### 3.6 Crossref 论文谱系（15 篇）——从 LBS/DQS 到 motion matching

- 蒙皮：DQS（`W10A-066`）与 QTangent 变体（`W10A-067`）；姿态空间形变（`W10A-075`）；PCA 动画降维（`W10A-076`）。
- IK：FABRIK（`W10A-069`）、拟人肢体综述（`W10A-070`）、人臂解析解（`W10A-071`）、FABRIK 独立复现（`W10A-081`）。
- 运动合成/编辑/重定向：motion graphs（`W10A-068`）、verbs/adverbs 插值（`W10A-072`）、重定向（`W10A-073/079`）、
  分层编辑（`W10A-074/080`）。
- 数据驱动：motion matching 词条（`W10A-077`）与 learned motion matching（`W10A-078`）。

## 4. 与既有轮的接缝

- **与 w6d/w8b（资产与压缩）**：那两轮解决"动画数据怎么变小"（ACL/量化/RDO）；本轮解决"变小之后怎么在运行时正确求值"。
  接缝=clip 采样器的输入格式（量化/稀疏访问器）与插值模式的对应。
- **与 w8a（NPR/三渲二）**：NPR 的角色动画（夸张节奏、2D-in-3D、SDF 面部）需要本轮的表情（morph，`W10A-024`）、
  次级运动（弹簧骨，`W10A-065`）与运动变形（`W10A-053`）；风格与内容解耦的编辑口径见 `W10A-080`。
- **与 w9b/w9c（UI/组件）**：UI 动画（过渡/弹簧）与角色动画共享同一条"权重+回落+双缓冲"求值路径；
  LSSMJ 应只有**一套插值/求值内核**，UI 与角色是两个使用者（对应 C17 的关档逐位纪律）。
- **与 w9a（实时光影）**：角色阴影会因骨骼动画每帧失效阴影页（w9a `W9A-011`）——动画层要暴露"每帧失效源"标记，
