## 1. 它解决什么成本

- 目标：**几何保真度与对象数的数量级扩张**——"pixel scale detail and high object counts"（`W3A-003`）。
- 官方收益口径：几何复杂度提升若干数量级、LOD 全自动、LOD 过渡质量损失"罕见或不存在"（`W3A-004`）。
- 立论的核心原则（讲义正文）：**"should scale with screen resolution, not scene complexity"**（`W3A-085`）——
  屏幕就那么多像素，几何成本应按分辨率走。

## 2. 关键机制（逐条带锚）

1. **两段结构**：内部网格格式（数据面）+ 渲染技术（执行面）（`W3A-003`）——格式与执行器分离。
2. **全链路**：构建 → 流式 → 解压 → 剔除 → 光栅 → 着色（`W3A-002` 逐字）。
3. **簇化**：把三角形分组、为每簇建包围数据并按包围体剔除（讲义"Triangle cluster culling"节），
   **簇粒度 = 128 三角形**（`W3A-082`）；与 meshlet 的 126 上限同量级。
4. **LOD 树**：父节点是子节点的简化版本，运行期取"树的一个割"（view-dependent cut）；
   10k → 1M 三角形只多 **43% 树层级**（`W3A-084`）——层次结构的成本随规模对数增长。
5. **流式**：整棵树不必同时在内存，"任意割可当叶子、其余丢弃，按需请求"（讲义 Streaming 节）。
6. **规模口径**：讲义直言百万实例"轻松处理"（`W3A-083`）；摘要口径 10^12 三角形（`W3A-001`）。
7. **仍是三角形网格**：官方明确"Nanite meshes are triangle meshes"，只是带 LOD 与压缩（文档正文）。

## 3. 规模量级与代价

- 10^12 三角形 / 10^6 实例（`W3A-001/083`）vs 我们显示列表 10^2–10^4 条目——差 8 个数量级以上。
- **官方自认上限**：实例数、单网格三角形数、材质复杂度、输出分辨率需逐组合实测（`W3A-005`）。

## 4. 对本项目的取舍

- **不吸收**（整体）：场景量级完全不匹配；把 Nanite 拉进候选窗渲染器是负收益。
- **吸收（范式级，三条）**：
  1. **数据格式与执行器分离**（`W3A-003`）↔ 我们"显示列表 + CPU/GPU 两执行器"（设计 §3）；
  2. **成本按分辨率而非内容量走**（`W3A-085`）↔ 我们 damage/tile 设计的量化目标（内容变多不等于成本变多）；
  3. **层次结构对数级扩展**（`W3A-084`）↔ 未来 tile/内容索引的可行性论证；
  4. 官方"承认上限 + 逐组合实测"（`W3A-005`）↔ ADR 的"否证条件"字段格式。
- **可复用纪律**：流式/剔除/批分层（`W3A-002`）与我们 damage 三层（版本号 → tile 比较 → 树 diff）同构，实现不同。
