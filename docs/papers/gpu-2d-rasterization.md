## 1. 它解决什么成本

- 传统路径填充=CPU 扫描线（"三十年来 2D 标准依赖 CPU 做填充与描边"，`W3A-029`）——在高分辨率/高帧率下
  CPU 光栅成为瓶颈；GPU 路线要把**覆盖判定**搬到并行硬件。
- 但"GPU 更快"不是自动成立的：Pathfinder 作者实测**现有 GPU 字形方案有小字号慢等两个主要问题**（`W3A-067`）。

## 2. 三条填充路线（机制一句话）

| 路线 | 机制 | 锚 |
| --- | --- | --- |
| Stencil-then-Cover | stencil 步判覆盖、cover 步着色，接口显式解耦 | `W3A-030/031` |
| 凸包三角 + 片元判定 | 内部三角直接填充；边界三角带 u/v，像素着色器判内外 | `W3A-032/033/034` |
| 解析覆盖 / 随机访问 | 多项式滤波器解析求覆盖；每像素可随机访问几何 | `W3A-035/036` |
| 工程化（Rive 2023） | 路径归约为"唯一三角形补丁"，交硬件光栅器 | `W3A-069` |

旁注：Rive 自述**因多渲染器矩阵（Skia/Canvas）导致特性无法跨平台上齐**才自研单一渲染器（`W3A-070`）——
这是"多后端=特性矩阵"成本的一手证词。

## 3. 2D GPU 管线的成熟骨架（Levien 三代，`W3A-052..059`）

1. 结论先行：依赖现代 compute，2D 直接上 GPU"可行且质量/性能都有希望"（`W3A-052`），但作者**刻意只做 Metal 2.1**（`W3A-053`）。
2. 结构：给每个元素标**包围盒** → 分箱（sort-middle，借鉴 Laine & Karras 2011）→ 逐 tile 处理（`W3A-055/056`）。
3. 细节：跨 tile 边界的路径段用 **backdrop 原子计数**（+1/-1）替代全局排序（`W3A-058`）。
4. 自评："**Every cost in the pipeline has a reason**"——可解释性是其性能主张的一部分（`W3A-059`）。

对照物：NanoVG=面向 UI 的轻量抗锯齿矢量库，画布式 API（`W3A-075`），质量开关（stencil 描边）只在宽描边可见（`W3A-076`）；
Vello 拆出 **vello_cpu**（多线程/SIMD）与 GPU 版并列（`W3A-071`）——"同一渲染器双档"的外部先例。

## 4. 对本项目的取舍

- **候选窗主路径不变**：字形走"覆盖率掩码 + 图集/直存"（青简现状），矢量填充仅在图标/复杂形状上评估（有界吸收，
  `W3A-031`）。GPU 字形（Pathfinder 路线）**不吸收**，理由是作者自述的小字号问题正落在我们的字号区间（`W3A-067`）。
- **有界吸收（4 条）**：
  1. 元素包围盒 → 分箱/tile（`W3A-055/056`）——我们 CPU 侧对应 damage 分箱，GPU 侧对应区间批；
  2. backdrop 计数（`W3A-058`）——GPU 档分箱时的跨边界处理处方；
  3. 保守包围盒（`W3A-056`）——宁多画不误删，与 damage 联合矩形同原则；
  4. "每步成本可解释"（`W3A-059`）——写进性能报告模板。
- **不吸收**：解析覆盖（`W3A-035`）与其同族随机访问（`W3A-036`）在 CPU 侧比 2-bit 超采样贵；GPU 侧我们暂不做矢量填充。
- **反面模板**：`W3A-053`（只做单后端）提示我们 GPU 档应先单后端验证再谈跨后端。
