## 1. 终局目标（两个主目标 + 一条风格极 + 一条定位与一条工程面，用户 2026-10-03 确认）

| # | 目标 | "达到"的定义 | 反目标（明确不做） |
| --- | --- | --- | --- |
| **G-A** | **真实画质（photoreal）** | 场景档能在目标硬件上跑出：物理化 PBR + 实时 GI/RT 混合档 + 影视级后处理最小集（ACES/TAA）+ 大世界流送；对拍参考渲染器（光线追踪离线）在固定场景上收敛到可接受误差 | 不做影视级离线全局光照机；不做主机独占特性 |
| **G-B** | **三渲二（NPR／风格化）** | 3D 资产在引擎里呈现**2D 动画级观感**：阶梯/ramp 光影、稳定可控描边（内/外线）、面部等痛点区域的定向求解（SDF 脸等）、法线编辑管线可用；与 G-A **共用同一内核**（几何/可见性/纹理/合成不复制） | 不做 Live2D 式纯 2D 管线；不做逐帧手绘工作流替代 |
| **G-B2** | **泡沫时期科幻动漫画质（anime film look，G-B 下的风格极）** | 赛璐璐观感 + 胶片电影感可复现：颗粒/Halation/印片级调色/霓虹辉光/走片抖动，且**不降质**（与 TAA 等既有链的冲突有明确解法）；效果全部**显式开关+默认档冻结** | 不内置任何受版权素材；不牺牲稳定性换取"味道" |
| **G-C** | **通用性（不只是游戏）** | 同一内核服务三条产品线：桌面应用（工具/播放器类，Mineradio 为迁移样本）、创作/专业软件（文本书写、矢量、长列表）、游戏；UI 档与场景档可独立使用、可组合 | 不做"游戏专用"假设（如默认全屏独占、只认控制器输入） |
| **G-D** | **前端语言迁移引导（Rust 内建）** | 为 JS/TS/CSS 背景的开发者提供迁移路径：声明式 DSL/样式子集/（可选）WASM/JS 引导层，让"前端写法"能落到本引擎的显示列表与失效模型；**引导层不得进入内核热路径** | 不内嵌完整浏览器；不承诺 100% Web 兼容 |

三者的共享底线不变：**显示面位图契约 + 跨平台像素级一致 + 先量后改的门禁纪律**。压缩类技术一律**视觉无损优先**，凡"降质换体积"必须显式标注并默认关闭（ADR K）。

### 1.1 优先级与资源取舍（用户 2026-10-03 口径）

1. **P0 · 实时光影（游戏向）**——渲染引擎的**第一战斗力**；场景档的基础件（阴影/多光源/AO/GI/混合）按游戏关键路径排序推进（主链次序见 `../papers/real-time-lighting-deep.md`（w9a））。
2. **P1 · UI 与组件体系**——显示面（M1）已有契约；**组件层为独立支柱**（事件/焦点/无障碍/主题令牌/复杂组件/工作区；任务表轨 9/10）。
3. **P2+ · 条件目标**——G-A/B/B2 的扩展与 G-C/G-D 的功能深度：**"没钱就不搞"=排序策略而非放弃**——每条目标保留判据与证据锚，资源具备时按任务表直接启动。
4. 所有"提速/提效"改动遵守 **C17 优化等价性**：**质量不变的前提下提升**——默认档输出必须逐位相同（或落在对拍阈值内），否则按降质处理（与 C14 同族纪律）。

### 1.2 范围边界（用户 2026-10-03 口径）

本项目交付 = **渲染引擎 + 前端范式**：显示面（布局/文本/光栅/合成）、场景档（几何/纹理/光照/阴影/可见性/压缩）、
显示链与色彩管理、UI 运行时与组件体系、**输入系统**、无障碍、动画运行时、资产管线、工程门禁。

**明确不在范围**（不做分析、不做设计、不占轮次）：

- **物理/碰撞/刚体**——用户侧已有实现；本项目只保留与渲染/动画的接缝（变换、可见性、根运动），不深入物理本体；
- **音频引擎、网络/多人、通用国际化架构、编辑器/工具链产品、通用资源/内存分配器、视频内容链**
  （平台解码 API 已作能力记录，不再展开）。

> 口径来源：用户 2026-10-03 对缺口盘点的回复——"你只是个渲染引擎 只不过加前端范式 输入系统倒是可以搞
> 物理引擎我已经搞了 但不是你的事情 包括下面其他的不关你的事"。

**crate 布局**（依赖单向，细节在 `README.md` §3；NPR 轨不新增 crate，只新增 shading/描边模块）：

| crate | 职责 | G-A | G-B |
| --- | --- | --- | --- |
| `lssmj-core` | 几何/颜色/Frame/DisplayList/命中 | ✓ | ✓ |
| `lssmj-text` | 字体清单/整形/字形（含图集档） | ✓ | ✓ |
| `lssmj-raster` | CPU 光栅（扫描线+2bit AA+RLE） | ✓ | ✓ |
| `lssmj-render` | 布局→显示列表→damage→合成 | ✓ | ✓ |
| `lssmj-assets` | glTF/KTX2/ACL/Draco/meshopt（+法线编辑资产） | ✓ | ✓（+法线管线） |
| `lssmj-shading` | 材质/光照模型枚举 | PBR 族 | ramp/NPR 族 |
| `lssmj-post` | 后处理链 | TAA/ACES/bloom | 描边/网点 |
| `lssmj-gpu` | wgpu 执行器（三级降级） | ✓ | ✓ |
| `lssmj-shell-*` | 贴图/输入/IME | ✓ | ✓ |

**共核纪律（写成门的判据）**：几何/可见性/纹理/合成**只允许一套实现**；风格层差异只能出现在
`lssmj-shading` 与 `lssmj-post` 两个 crate 的接口内部——由 C13（两管线同资产不漂移）机器守。

**NPR 共核的现成样本与实现形态（第六轮落盘，`w8a` 109 条）**：Unity Toon Shader 3 用**一份光照核**
同时服务 Built-in/URP/HDRP（W8A-040/044）；kShading 证明"**同特性只换阶梯化 BSDF**"成立
（对 GGX 镜面项做 step 量化、两瓣，W8A-063/064）。据此：`lssmj-shading` 的派发粒度=
**per-object/逐部位覆写 + Step/Feather/ramp 参数**；描边层=**可开关**（inverted hull 或后处理边缘，
W8A-006）；GGXrd 的"弃法线贴图+手工法线+逐角色专光"是风格资产管线的参考（W8A-002/004/010）。
**最强否证风险**：逐角色专光与全局时变光/GI 同开的光照双模问题——第一实验=小场景 G3 实测（任务 T-NPR-11）。
