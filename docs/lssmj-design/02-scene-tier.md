# 02 · 场景档设计（LSSMJ 的第二层：从 UI 位图到场景/3D）

> 背景：第一层设计（`README.md`）只覆盖"显示面 UI"（候选窗/面板/overlay）。用户 2026-10-01 追加要求
> "纹理/光追/光照/论文都要研究"——本篇把第四轮（R1–R5 + 图形 API + 视频）的结论落成**场景档的取舍与判据**。
> 规则同上层：每个判决 = 学谁 / 弃谁 / 证据锚 / 否证条件；证据不足处标"待测"。

## 1. 与 UI 档的关系（不推翻，只向上扩展）

- 显示列表（`README.md` §3）是两层共用的"描述"：UI 档的项是`矩形+UV+文本 run`，场景档的项是`网格实例+材质+变换`。
- 位图契约（`w5a`）在两层都成立：**壳只贴"最终帧"**；GPU 档只是把"光栅执行器"从 CPU 换到 wgpu。
- damage/脏区纪律（§4.3）在两层同构：UI 档是像素级可见性，场景档是**对象级可见性**（剔除，见 §4）。

## 6. 资产柱（第四轮 R4 结论）

- 格式：glTF 2.0（核心+扩展+回退，W6D-001/004）；构建期：几何 Draco/meshopt、动画 ACL、纹理 Basis/KTX2（W6D-003/013/016）。
- **ACL 的两条纪律直接采用**："体积即性能"（W6D-007）与"常量/默认轨折叠"（W6D-012）。
- 着色器：WGSL 为源语言（W6D-015），naga 转译，构建期离线编译（与 `w3f` W3F-050 的 Impeller 纪律合并）。

## 8. 视频边界（用户点名批次结论）

- **视频不进渲染内核**：壳层能力（平台解码或 FFmpeg 类），接口按 GN `cVIDEO` 三要素（帧驱动推式更新/时间同步开关/音频支路，W6G-006..008），零拷贝进纹理是壳实现。
- 依据：Chromium 把解码器当管线节点（W6G-004）；GN 的"每帧必须推"契约（W6G-008）；Mineradio 的子系统切分（w4b）。

## 10. 路线图增量（接上层 P4 之后）

- **P5 场景最小闭环**：显示列表扩网格项 + wgpu 执行器 + CSM + 烘焙 GI（静态）。
- **P6 大世界**：SVT/流送 + HLOD/World Partition 式单元 + 距离/视锥/遮挡三级剔除。
- **P7 动态光**：软光追等级序（屏幕→远场）+ 降噪（SVGF 类）+ ACES 链。
- **P8 虚拟几何**：Nanite 式簇树（在前七步的预算数据上立项，不许跳步）。
