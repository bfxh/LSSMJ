# GN SDK 02 · G2D、布局/显示列表、字体图与 UI 组件树

## 2.1 G2D 绘制模型（`Include/_Graphics/GN_G2D.h`）

**全局状态机式 2D**（与 DirectDraw 时代一致）：视口/状态重设（`GT_ReSetRenderView2D` `:39`、
`GT_ReSetRenderState2D` `:42`）、显示剪裁区"**绝对屏幕窗口坐标**"（`GT_ScissorEnable` `:45`、
`GT_ScissorRectSet` `:48`），提交在 `GF_ScreenUpData()`（`:160`）与 `RenderFinish()`（`:155`，注释：
"帧循环框架下在每帧绘图内容提交给屏幕前都会自动调用该函数一次"）。

**图像对象 `sIMAGE` 是纹理图集的装载单位**（`:52`，注释标 ★★★★★）：

- 非 2 的幂纹理用 `uRange/vRange` 装填："有时要保存 369 大小的图需要开一张 512 大小的纹理来存放，
  那么 uRange 的值为 图像实际大小/装填图像的纹理大小"（`:57`）；
- `texture` 是**纹理数组**（序列帧动画），`texnum` 计数（`:59`–`:60`）；
- 异步加载：`IsReady(texID)`（`:96`）、全局 `GN_SetVMemLoadMode(GNg_eVMEM_SYNC/ASYNC)`（`:174`–`:175`）；
- **渲染目标**：`BeginRender(msaa, _3d, isnew)/EndRender()`（`:99`–`:101`）——"3D 模式下渲染到的图象为翻转的"；
- 能力查询：`RenderTargetSupport()`（`:104`，"2005 年后的 PC 独显…都支持"）、`RenderSupportNON2()`（`:113`）。

**绘制原语**：`ImageLoad`（`:127`，支持"短名+序号 `0000.png`"的含糊读取，注释还提到保密资源的 `.gim` 约定 `:125`）、
`ImageDraw`（两版，第二版带 UV `:133`；注释特别提醒 UV 要乘 `uRange/vRange` 以跨平台一致）、
**`ImageDrawMP`（一组排位数组一次画多个 `:136`）**、**`ImageDraw4P`（任意四角点=带旋转 `:149`）**、
`LineFrame2dDraw`（`:152`）。→ 这就是该年代引擎的"批处理"形态：状态机 + 多位置绘制，
**没有现代意义上的批键/实例化**。

## 2.2 布局 = 锚点 + 排列格式 + **显示列表**（`GN_Layout.h`）

- **锚点定位**：`NearRectRangeGet` 用 `near_pointU/V ∈[0,1]` 把"里区"摆进外区（`:19`–`:27`），
  定点版用 0–65535 映射（`:24`）——UI 靠边/居中全部由此实现（`GNu::eNEAR_TYPE` `:5`）。
- **文本/图元排列格式 `sARRANGE_FMT`**（`:36`）：填满矩形、锚点、字距/行距（0=自动）、
  宽高（**负值=镜像翻转** `:43`–`:44`）、自动换行（`eENTER_*` `:31`）、
  **`erect_print` 竖向排列（`:46`）与 `overturn_print` 反向排列"如汉字古文从右到左"（`:47`）**。
- **布局产物 = 显示列表**：`ComputeArrangeRangeData`（`:115`）输出一段 `sDRAW_RANGE` 数组
  （每个单元 `x,y,w,h,u1,v1,u2,v2,tid,strid`，`:95`–`:102`：位置/尺寸/贴图 UV/**贴图索引**/**字符索引**），
  并回填每行起始可视单元表 `row_sids[256]`（`:130`）。**硬上限：一行 ≤256 单元、≤256 行**（`:135`）。

> 含义：GN 的"布局"与"绘制"是**分离**的——排版一次产出带 UV 的四边形列表（含字符索引供命中），
> 绘制时按列表喂状态机。这与青简渲染器"measure→draw 双整形"是同一问题的两种形态；GN 的
> 显示列表把"排"与"画"解耦，但**每帧仍需按状态机重绘**。

## 2.3 文本 = GB2312 点阵字体图 + 艺术文字输出器（`GN_Font.h`）

- **字体是图**：`eFONT_MAP_FORMAT { eFONT_NUMBER, eFONT_ASCII, eFONT_GB2312 }`（`:65`–`:69`），
  即"字体图"一图含字模；`QueryFontMapFormat` 查询（`:75`）；缺字处理三档
  `eFONT_MAPLACK_SHOW_{NULL,CUBE,DEFAULT}`（`:70`–`:74`，立方体占位/系统默认）。
- **`cTEXT_ART` 艺术文字输出器**（`:79`，★★★）：`Init(font_map, sARRANGE_FMT*, lack_mode)`（`:104`）；
  `sDRAW_ARRANGE` 保存"排好绘制单元范围 + 每行起始 ID"（`:17`–`:38`，`zRowSIDs[256]` `:21`）。
- **核心性能约定（可直接搬进任何 UI 设计）**：`SetText`（排版，`:115`）与 `Show`（显示，`:120`）
  分离——注释原文："**用 SetText 与 Show 两个组合灵活运用运行效率会比 OutText 高** 因为同一个输出对象
  显示本文内容或显示位置等产生变化才有需要调用 SetText 平时更新重绘画面时仅调用 Show 即可"（`:119`）。
  这与"保留模式每帧只重绘"的结论同构；`OutText` 是"排+画"一次的便利函数（`:110`）。
- **逐字符命中**：`GetVIDfromCoord(px,py,…)` 返回"选到的字符 ID + 行号 + 位置信息"（`:126`）；
  `GetVIDfromText` 反向（`:123`）——命中测试内建于文本输出器（对照青简：命中表只做状态条）。
- 变体：`cTEXT_ARTEX` 支持"**标签文本**"（`:166`）：指定子串着色并回调点击
  （`LableSet/LableSegmentGen` `:177`–`:179`，注释给出了调用顺序与"不要每帧调用"的成本警告 `:193`）。

## 2.4 UI = 保留式组件树 + 序列化（`GN_UI.h`）

- **组件基类 `iUI_OBJECT`**（`:74`）的协议：`StatisticSize`（向父组汇报占位并撑大父组 `:81`）、
  `OnRePos/OnMove`（父组尺寸/位置变化时回调 `:82`–`:83`）、`UpdateRun(dt, parent链)`（`:84`）、
  `GetDrawArea`（算实际绘制区 `:85`）、以及 **`DataSave/DataLoad`——每组件自带二进制序列化**
  （`:88`–`:91`，段首"版本号 1 字节 + aType 4 字节"，用户自定义组件版本号从 1 起）。
- **组 `cUI_GROUP`**（`:110`）：更新后得绝对矩形 `gx/gy/gw/gh`（`:113`–`:114`）、
  **`aUsScissor` 组内剪裁**（`:116`）、`Comment()` 接入子组件（`:136`）、`cUI_PTR` 管层级与
  `OrderMove` 调层序（`:309`–`:320`）；父组可有 `lw/lh` 最小尺寸参与统计（`:112`）。
- **事件模型**：全局回调指针 `UiActionCall(uobj, action)`（`:97`）+
  `RecvInputUiObject/RequestInputUiObject` 两级"谁在收输入"（`:99`–`:100`）；
  `eUI_ACTION_TYPE` 定义动作值域（选择 ID 1–65535、取消为负、`eUI_ACT_VANISH=65536` 消失等，`:31`–`:47`）。
- **组件家族**（`:5`–`:27`，20 类）：底筐（**支持九宫格平铺、模糊等级 1–4、边框拖拽缩放、顶栏拖动**
  `cUI_BACK_FRAME` `:172`–`:181`）、靠边图像、动画图筐/发射器（>`:194` 起）、静态文本、
  输入筐、调色板、滚动筐/列表/嵌套列表、图标/文本选择列表、列表树、文件浏览、简单对话框、
  选择按钮联、分页栏、滑动条、**触屏虚拟按钮/摇杆**（`:23`–`:24`）。
- **场景与文件**：`cUI_SCENE::InitLoadToData(.gui 专属文件, progress)`（`:346`）、
  `SaveToFile(version, exp_img)`（`:349`）、当前文件版本 `GNu_SAVE_GUI_VERSION 0`（`:357`）、
  共享对象收集器 `cSHARE_DATA`（`:49`，保存/加载时对图像/文本/式样去重）；
  组件名查找表 `zObjNameTable/zObjNameBuf`（`:331`–`:332`）。
- **文本输入筐 `cTEXT_INPUT`**（`GN_UiTextIn.h:28`，★★）是全库最"现代"的组件：
  输入类型含密码/浮点/带符号/16 进制（`:19`–`:27`）；**IME 状态位**（`zImeIn` `:82`）；
  以"记录列表"实现的**撤销**（`zSaveList` `:105`，`aMaxCancelNum` 上限 `:116`）；
  筐内偏移含"阻力/速度"参数（`:75`–`:77`）；焦点闪烁（`:95`–`:96`）；
  `P<GNg::sIMAGE> zRetArrow`（`:107`）——**"返回主显示模式的按钮图标"**，即移动端"主显示"交互的一部分：
  `SetPrimary(nearU,nearV,refer_focusU,refer_focusV)` 把输入框临时放大突出（`:157`）。

## 2.5 对 LSSMJ 的取舍（本篇结论）

| 项 | 锚 | 判定 |
| --- | --- | --- |
| "排一次（SetText）/每帧只 Show" | `GN_Font.h:119` | **吸收**：与保留模式/脏标记同构，是成本纪律的早期形态 |
| 布局产出"带 UV + 字符索引的显示列表" | `GN_Layout.h:95`–`:135` | **吸收（形态）**：显示列表=布局与绘制解耦的载体；但需换掉其 256×256 上限与全局状态机执行器 |
| 逐字符命中内建（GetVIDfromCoord） | `GN_Font.h:126` | **有界吸收**：候选窗不需要逐字符命中；文本输入框需要（光标/选中） |
| 字体=整幅点阵字库图（GB2312） | `GN_Font.h:65`–`:69` | **不吸收**：点阵字库的时代约束；现代路线是矢量整形（cosmic-text/swash）+ 按需字形缓存 |
| 组件树 DataSave/DataLoad 自带 | `GN_UI.h:88`–`:91` | **吸收**：UI 即数据的序列化协议（版本号前缀）值得借鉴到 LSSMJ 的界面描述文件 |
| 全局回调 + 两级输入占用（Recv/Request） | `GN_UI.h:97`–`:100` | **有界吸收**：简单可预期；现代做法应改显式事件队列+焦点栈 |
| DirectDraw/D3D9/es1 兼容层 | `GN_G2D.h:178` | **不吸收**：我们的目标平台没有 2011 年前设备 |
| 资源缺失的失败模式（字体图找不到 → 日志行） | `RunLog.txt:1` | **吸收（教训）**：字体资源缺失必须"可定位可回退"——青简的 `NoUiFont` 回退链即正面案例 |
